# v0.2.8 运行时审查与测量

本次审查以 v0.2.7 为发布基线，覆盖 Rust 工作区、Python 和 TypeScript SDK、网页通道以及构建与发布工具。下表按触发条件和修复位置计数，共 16 项。其中 12 项涉及行为、交付或版本信息，4 项涉及资源增长或处理开销。测试数量与缺陷数量分别统计。

| 编号 | 对象 | 触发条件与处理 |
|---|---|---|
| 1 | 插件发现 | 移动来源目录后重载配置，重新扫描可变来源，保留实例已确认的安装副本。 |
| 2 | Python 调用超时 | 已发出的请求超时且管道拥塞时，取消通知进入控制队列，调用方按期收到超时。 |
| 3 | 原生库卸载 | 在主动卸载模式下，宿主等待库级 Tokio 工作结束和租约归零。旧插件以保留映像方式退役。 |
| 4 | 进行中的效应清理 | 已显式释放的效应保留至实际清理结束，实例重启会等待；卸载过程中登记的效应也由该次卸载收束。 |
| 5 | 等待依赖的实例 | `Pending` 实例销毁时仍会清理通过其上下文登记的监听与其他效应。 |
| 6 | 并发依赖通知 | 服务绑定记录通知修订，较早的就绪检查失效后放弃写回，保留较新通知的结果。 |
| 7 | 退役错误 | 描述符释放失败时保留映像，并把错误码和库编号交给管理调用方。 |
| 8 | 换库失败时的资源增长 | 单项与批次候选撤销后，监管器按实际退役数检查阈值，使用已确认的部署恢复。宿主按进入静止状态的库回收，退役计数随状态变更更新。 |
| 9 | 子实例挂载与父实例销毁 | 在挂载效应内部登记子实例的生命周期句柄，使父级清理能正确撤回该句柄。 |
| 10 | TypeScript 分片接收开销 | 完整帧直接解码，分片帧按已收数据扩容，避免每个分片重新复制整个前缀。 |
| 11 | 发布目录递归复制 | 发布源目录包含装配目录时，工具在开始复制目录条目前返回路径错误。 |
| 12 | 半成品归档 | 在输出文件系统完成压缩和同步后，原子发布正式文件名；既有同名归档受到保护。 |
| 13 | 并发打开页面通道 | 在同一宿主内按核心确认顺序分配通道编号，多个同时打开的页面共用这项次序。已打开通道的收发继续独立进行。 |
| 14 | 发布包版本信息 | HTTP 插件内置网页 SDK 的版本取自网页包清单，进程 SDK 版本取自其自身清单。 |
| 15 | 核心库编号的历史占用 | 状态查询保留当前连接与最近换库报告所引用的编号，回收已退出连接的其余映射。 |
| 16 | 状态快照的实例匹配开销 | 生成快照时按名称匹配部署声明，替代逐个声明扫描全部实例的做法。 |

## 验证范围

Rust 工作区 36 个包的全部目标通过编译检查与 Clippy 检查。选取内核、原生 ABI、宿主、监管器、运行时、传输协议、接口生成、打包、网页生命周期和文档示例等共 319 个不同的 Rust 测试，其中包含驱动真实浏览器的集成场景。Python 实际管道取消和套接字背压用例各通过一次。原生动态库的释放回调返回错误码 47 时，宿主对管理请求返回同一错误码，保留旧映像。

候选拒绝场景分别经过单项替换和批次替换的公开入口。以阈值 0 触发有状态重启后，候选的原始错误仍返回调用方，重新启动的原服务保持计数 137。性能样本见下文。运行验证平台为 macOS Apple Silicon。

## 原生热替换

macOS Apple Silicon 上运行仓库 AC-9 场景，使用 release 编译的原生插件和 Rust 1.85 编译的消费者。8 个工作线程经历 50 轮换库，计数状态保持为 137。有状态整组重启发生在第 21 和 42 轮。

| 指标 | 本次观测 |
|---|---:|
| 每轮受影响实例，中位数 / 最大值 | 3 / 4 |
| 换库停顿，中位数 / 最大值 | 181 / 1,121 ms |
| 管理操作耗时，中位数 / 最大值 | 193.029 / 1,139.725 ms |
| 原生宿主 RSS，第 20 → 21 轮 | 21,056 → 6,672 KiB |
| 原生宿主 RSS，第 41 → 42 轮 | 20,960 → 6,672 KiB |
| 核心 RSS，开始 → 第 50 轮 | 8,720 → 10,096 KiB |

RSS 是采样时操作系统报告的进程驻留内存。重启回收了旧宿主占用的内存，也产生了同组实例共同恢复的停顿。这里的负载来自仓库场景，MathBook Studio 的业务数据和运行进程均独立于该测量。[热替换场景](../../crates/cordis-runtime/tests/stress.rs)

## TypeScript 收帧

在 Node v26.13.1 中，对 v0.2.7 与本版使用相同的 UP/1 编解码器、请求、应答和分片。每轮接收四个 2 MiB 字节结果，输入分片为 8 KiB，首个帧头跨分片。两个版本各预热一次，再交替测五轮。计时覆盖 SDK 收帧、解码和应答交付，交付后逐字节比较数据。两版的五轮中位数分别为 **33.01 ms 和 1.08 ms**。这一结果衡量进程内收帧路径，网络、插件业务执行和磁盘传输另行计时。[收帧实现](../../sdks/typescript/cordis-sdk/src/wire.ts)
