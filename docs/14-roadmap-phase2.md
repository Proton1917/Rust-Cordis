# 实施次序与交付验收

目标架构的第一批验收事实来自已有应用。新分组、固定调用入口和跨目录构建分别有清楚的使用者，旧版运行结果见[历史记录](history/progress-2026-11-16.md)。

## 共享宿主

用相同的业务插件和输入，对比原部署与共享部署。观察进程数、线程数、物理内存足迹、日常调用延迟。替换一个提供方时，其依赖方重新绑定；无关实例保留身份。宿主退出时检验该组的实际重启范围。既有清单继续使用原分组规则。

## 原生契约

分别编译提供方和消费方，检查业务方法追加、声明顺序变化和不兼容签名各自得到的结果。执行过程中替换提供方时，旧句柄应报告退役，缓冲和异步资源归还所有者。对比同组调用与完整业务操作耗时；两种测量的起止位置各自记录。

## 大结果与恢复

提交一次会产生完整清单的业务操作。调用方经小回执得到已提交的快照，返回通道中断后凭业务操作标识查询原结果。完整数据按流读取；对照源数据确认内容，对照业务记录确认提交次数。

## 独立应用交付

从源码与部署目录分开的干净工程构建，在另一目录启动实际包。替换一个插件，读取在线和停机后的程序来源；只靠公开清单和工具输出即可定位运行版本。已有 ABI 主版本的应用按支持期运行。实现、环境或输入发生关联变化时，复核相应路径。原版组件行为继续采用[一致性矩阵](04-conformance.md)。
