Rust-Cordis

Cordis 运行时核心

是一个长期运行的 Rust 程序。软件的功能全部以形式提供：数据存储、业务逻辑、网页、AI 调用各自是单独编译的插件，在核心运行期间插入、拔出或更换。核心不包含业务功能，负责插件的启动与停止、插件之间的连接，以及插件移除后的清理。

插件拔出后不留残余插件运行时打开的文件、提供的服务、注册的页面都作为记在核心里。插件停止时，核心按顺序全部撤销。
依赖变化时自动重连插件声明自己需要的服务（）。服务出现时插件启动，服务更换时插件重建，服务消失时插件进入等待。
插件故障不影响核心插件运行在核心之外的独立进程中。插件崩溃后，核心按记录收回它的全部效应，并重新启动它。

    结构

    进程结构

    核心进程只运行核心自己的代码。插件全部运行在核心之外的进程中，与核心之间通过 消息通信。插件中的段错误、死循环、内存错误只影响它所在的进程。

    唯一的内核系统中只有一个，位于核心进程。实例的启动、停止、更换顺序由它决定，插件进程按核心的指令执行。
    高速插口与插件组Rust 插件编译为动态库，经由 装载。同一的插件在同一进程中直接调用。
    通用插口Python、TypeScript 等语言的插件是普通程序，经与核心收发消息。核心不包含这些语言的运行环境。
    前端插件前端代码同样是插件，经通用插口接入。浏览器页面是，不含内核；页面的消息由 http 插件转发给核心，核心本身不监听网络。
    挂载

    插件的挂载过程

    1. 读取配置

      核心读取 ，得到要运行的实例、各自使用的插件、配置和插件组。

    2. 启动插件进程

      Rust 插件由 cordis-host 装入动态库，Python 插件由 python 运行，TypeScript 插件由 node 运行。

    3. 握手

      插件报告名称、版本、包含的、每个组件需要和提供的服务。版本不兼容的插件在此被拒绝。

    4. 挂载为实例

      核心为每个组件生成一个，交给内核管理。所需服务不全时，实例处于“等待中”。

    5. 启动

      所需服务齐全后，内核向插件进程发出 apply，插件执行自己的启动代码。

    6. 记录效应

      插件每打开一项资源、提供一项服务、注册一个页面，都以一条消息报告核心，内核记入该实例的。

    7. 停止与撤销

      实例被拔出、更换或依赖消失时，内核按效应记录逆序撤销。插件一侧的清理动作由核心发消息通知插件执行。

    插件代码在插件进程中执行，效应记录保存在核心中。插件进程崩溃后，核心依据记录完成回收。

    职责

    核心的职责

    实例启停启动、停止、重启每个实例。这一决定只由核心作出。
    依赖管理服务齐全时启动使用方，服务消失时先停使用方，服务更换时重建使用方。停止顺序为先使用方、后提供方。
    效应记录记录每个实例的服务、监听器、资源；实例停止时按后进先出顺序全部撤销，每项至多撤销一次。
    热替换与回滚导出状态、卸下旧版本、装入新版本、交回状态；新版本出错时换回旧版本。替换请求来自启动配置，或来自获得授权的插件。
    进程监管启动插件进程，检查版本兼容，处理超时、消息洪泛与崩溃；崩溃后收回服务并按策略重启。
    消息路由转发不同进程中插件之间的调用与事件。
    准入与存档拒绝版本不兼容或未通过验证的插件；定期保存，退出时导出全部状态。

    由插件提供的功能

    • 业务逻辑与计算
    • 网页与界面
    • 数据库与文件格式
    • HTTP 与网络协议
    • AI 调用与工具注册
    • 桌面窗口
    • 管理后台与插件更新（经授权的管理接口）
    • 文件变化后的自动热替换

    核心只包含插件管理所需的功能，规模小、变化少，约每年升级一次。脚手架、代码生成、打包等开发工具在独立程序 cordis-dev 中，与核心分别升级。

    插件

    插件的写法

    一个组件声明需要的服务，在 apply 中完成启动，并把需要撤销的内容登记为效应。插件编译后放入插件目录，在 cordis.toml 中增加一条实例配置。
