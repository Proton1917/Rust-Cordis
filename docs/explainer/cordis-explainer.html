    结构

    进程结构

    原生库在 中执行。脚本和浏览器使用各自的语言环境，所有实例的启停由同一内核决定。跨进程交互使用 。

    唯一的内核系统中只有一个，位于核心进程。实例的启动、停止、更换顺序由它决定，插件进程按核心的指令执行。
    高速插口与插件组Rust 插件编译为动态库，经由 装载。同一的插件在同一进程中直接调用。
    通用插口Python、TypeScript 等语言的插件是普通程序，经与核心收发消息。核心不包含这些语言的运行环境。
    前端插件浏览器页面是，执行组件的启动、界面更新与清理。http 插件把每页的 WebSocket 转为独立的 UP/1 连接，核心管理该页的子实例、服务域与调用预算。
    挂载

    从程序来源到活跃实例

    1. 读取配置

      核心读取 ，得到要运行的实例、各自使用的插件、配置和插件组。

    2. 启动插件进程

      Rust 插件由 cordis-host 装入动态库，Python 插件由 python 运行，TypeScript 插件由 node 运行。

    3. 握手

      插件报告名称、版本、包含的、每个组件需要和提供的服务。版本不兼容的插件在此被拒绝。

    4. 挂载为实例

      核心为每个组件生成一个，交给内核管理。所需服务不全时，实例处于“等待中”。

    5. 启动

      所需服务齐全后，内核向插件进程发出 apply，插件执行自己的启动代码。

    6. 记录效应

      插件登记服务与清理动作。文件与连接由插件取得和释放，内核掌握该实例的。

    7. 停止与撤销

      实例被拔出、更换或依赖消失时，内核按效应记录逆序撤销。插件一侧的清理动作由核心发消息通知插件执行。

    插件拥有文件与连接，核心掌握绑定与效应归属。程序退出后核心撤回相应服务，持久数据归原插件管理。

    职责

    核心的职责

    实例启停启动、停止、重启每个实例。这一决定只由核心作出。
    依赖管理服务齐全时启动使用方，服务消失时先停使用方，服务更换时重建使用方。停止顺序为先使用方、后提供方。
    效应记录记录每个实例的服务、监听器、资源；实例停止时按后进先出顺序全部撤销，每项至多撤销一次。
    热替换与回滚导出状态、卸下旧版本、装入新版本、交回状态；新版本出错时换回旧版本。替换请求来自启动配置，或来自获得授权的插件。
    进程监管启动插件进程，检查版本兼容，处理超时、消息洪泛与崩溃；崩溃后收回服务并按策略重启。
    消息路由转发不同进程中插件之间的调用与事件。
    准入与存档拒绝版本不兼容或未通过验证的插件；定期保存，退出时导出全部状态。

    进度

    发行版与目标设计

    v0.2.5 是已发布的运行时。下表区分该版本、随后主分支的源码以及下一版目标；新接口的运行性能以实现后的实测为准。

    版本使用者能观察到的行为
    v0.2.5 · 发行版显式分组共用原生宿主，ABI 1.1；核心停机后能查询最后确认的程序绑定。
    主分支 · 85860d8ABI 1.2 对新使用方比较方法布局；原生 SDK 支持库级 Tokio 上下文。
    下一版 · 设计阶段原生插件默认共享宿主，用稳定方法身份调用，工具负责从源码工作区装配部署。
    页面实例与依赖恢复每页的前端组件在核心中各有一个子实例，归属于网页实例或活动后端。页面服务按页面编号隔离，显式命名域也属于当前页面。必需提供方撤回时，子实例进入 Pending 并清理界面；提供方插回后重新执行 apply。关闭一页会回收该页子实例，其余页面继续运行。
    版本替换与连接恢复替换时逐页导出状态、清理旧组件，再加载带新序号的模块，保持同一页面文档。全栈替换先激活后端，再更新页面；候选失败时共同恢复原版本。HTTP 重启沿原地址轮换令牌，各页完成本地清理后重连。消息和在途调用预算按页面连接分别计算。
    外部 HTTP 与大文件处理方在激活时登记普通路由，卸下时撤回。HTTP 插件解析方法、头部、Cookie 和正文；通用字节流以服务对象转交，接收方按需拉取，取消时释放文件和套接字。页面外壳由应用提供，组件替换保持同一页面文档。
    调用身份与授权核心写入直接调用方：后端为 instance，页面为 page_of；页面键指向 HTTP 插件保存的连接属性。各插件决定授权，密钥插件按自己的 grants 读取文件并提供值。后端处理页面调用期间，仍以自身实例身份访问其他服务。
