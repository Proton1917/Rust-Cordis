# 插件、实例与资源的生命周期

插件是发布单元，一个插件可以提供多个组件。每次挂载组件产生一个实例。实例拥有配置、上下文、绑定、效应和临时资源。宿主、脚本进程和浏览器都是执行位置。业务职责决定插件如何划分，部署决定执行位置。

## 服务与版本

服务契约声明接口名、主次版本、方法、输入输出、错误和行为。使用方声明最低次版本，相符的提供方可以独立替换。兼容追加新方法或带缺省值的字段；已有方法的行为变化使用新主版本。WIT 生成器可为同一接口产生 Rust、Python 和 TypeScript 绑定。

## 一个实例的寿命

笔记组件依赖存储。先挂载笔记时，实例处于 `Pending`；存储出现后，笔记取得绑定并登记页面事件。移除存储时，笔记先撤回监听器，再由存储完成清理。新存储出现时，笔记得到新的绑定。其他作用域中仍绑定原提供方的实例继续运行。

由上下文登记服务、事件和子组件，内核记录归属与清理次序。插件取得数据库连接、文件或后台线程时，将相应释放动作登记到实例的效应中。外部存储与网络操作由业务插件按其持久性契约处理。

## 执行和等待

多个原生实例可以共用一个宿主的执行线程。阻塞代码占用线程时，要让协议通信与控制操作继续推进。调用第三方 Tokio 客户端的插件需要对应动态库的执行上下文。长任务采用提交、异步执行、按编号查询的业务接口，进度和取消由任务所有者决定。

## 状态与切换

周期检查点按实例保存。每个实例导出后立即解冻，后面的实例仍可继续导出。运行时在状态目录的 `<实例名>.state` 保存最近一次检查点，下次挂载直接读取。升级时先恢复中断的部署，再合并旧版 `consumed/` 中的检查点。两处都有同名检查点时，采用根目录中的版本。

状态块携带模式名、版本及不透明内容。提供方解释旧状态并迁移。替换前确定目标和会重新激活的依赖方，保存其状态和原部署引用。候选成功后发布新绑定；失败时依本次事务的原状态恢复旧定义。手动换回上一版本属于另一次部署，主分支以当前导出值交接。已经持久提交的写入由业务所有者回答。[批次规则](adr/0031-batch-replacement.md) · [状态交接](adr/0052-dependent-state-transitions.md)

## 实例资源的归属

| 编号 | 资源与释放责任 |
|---|---|
| PR-1 | 随实例运行的异步任务通过 `ctx.spawn` 归入对应效应。清理时由所有者终止并等待任务结束。 |
| PR-2 | 原生线程可通过 `ctx.spawn_thread` 登记，也可由实例效应创建，在该效应清理时通知退出并等待线程结束。 |
| PR-3 | 插件使用与其 SDK 版本匹配的异步执行上下文。直接通过库级 Tokio 创建的任务具有库级寿命。 |
| PR-4 | 全局缓存随库重建。跨替换的内存状态由导出器和后继实例交接。 |
| PR-5 | 插件以注入的接口、受管理的资源或事件交互。内部地址与全局变量留在其所属库。 |
| PR-6 | 文件和套接字在对应效应中取得，以登记的释放动作关闭。 |
| PR-7 | 持久数据保存到实例获准使用的数据目录，恢复时由同一数据所有者读取。 |
| PR-8 | 支持在原生边界捕获 panic 的库采用 unwind 策略。abort 会导致该宿主进程及其成员退出。 |

## 部署替换的九个动作

SW-1 准备独立候选副本与租约；SW-2 在启用验证时核对印记；SW-3 打开库并完成 ABI 握手；SW-4 校验受影响的接口契约。到此为止，已激活实例继续使用原实现。

SW-5 导出目标和受影响依赖方的状态，冻结需要交接的写入。SW-6 将新定义交给内核，依照依赖次序清理和重建。SW-7 等待部署目标达到其预期状态。SW-8 在配置的确认期间观察候选，失败时按本次事务保存的原状态恢复。SW-9 退役旧代码并回收可释放资源，公布新部署。源程序被覆盖后，已确认引用仍能用于恢复。恢复本身失败时报告实际失败与剩余有效状态。
