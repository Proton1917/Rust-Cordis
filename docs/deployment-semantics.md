## 部署对象

应用的声明给出实例名、程序引用、组件、配置、父视图、隔离域和分组。固定的产物提供组件描述以及状态模式。实例名在部署中唯一，加载纪元标识这次实例激活，连接编号标识一次宿主连接。三者各有独立寿命。

令系统状态为 $s=(D_c,D_p,R,T,P)$。$D_c$ 是已提交声明，$D_p$ 是本次候选，空闲时为 $\varnothing$。$R$ 是实例、服务绑定、连接、加载纪元和资源租约。$T$ 是受理队列、当前操作及有限的结果记录。$P$ 为各实例保留带模式与版本的检查点。已接纳的基础配置、管理覆盖和固定来源共同确定 $D_c$。替换操作持有的原状态与候选确认期间产生的状态分属两个时点。

| 事实 | 写入者、寿命和读者 | 实现位置 |
|---|---|---|
| 基础声明、管理覆盖、已确认程序来源 | Store 持有目录写锁直到进程退出。恢复和离线查询按照同一个日志标记选取版本。来源先由控制器观察实例激活，再作为确认记录发布 | `storage.rs`、`control/sources.rs` |
| 候选及原部署 | 一次部署操作自准备起持有，对照两份声明选择变化的实例；持久决定形成后释放原部署 | runtime、supervisor 的 `batch.rs` |
| 实际组件、配置、目标修订和运行纪元 | 内核纤程与特定加载代分别持有。旧代回调按旧代上下文执行 | `fiber.rs`、`registry.rs`、`manager/generation.rs` |
| 已解析绑定 | 内核反射服务按服务键与隔离域登记；消费者持有加载时接纳的具体绑定。服务名称相同的两个提供方有各自的身份 | `reflect.rs`、`service.rs` |
| 页面子实例 | 页面连接与父效应共同限定实例寿命，页面断开或父效应撤回时清理 | `cordis-web-deployment/src/pages.rs`、`manager/lifecycle.rs` |
| 连接健康与重启 | 监管器处理 EOF、进程退出与重启事件。查询采样错误随该次观察报告 | `manager/lifecycle.rs`、`status.rs` |
| 检查点及继承输入 | 导出器冻结时捕获一个版本，事务与加载代在进程内共享其不可变内容，跨连接时编码。业务数据库由组件持有 | `manager/lifecycle.rs`、`manager/generation.rs`、`storage.rs` |
| 原生对象、缓冲、运行中调用 | 宿主和对象持有来源库租约，源侧析构后归还。执行方实际结束决定同步调用的租约寿命 | `cordis-abi/src/buffer.rs`、`cordis-host/src/lease.rs` |
| 票据与完成结果 | 接收方按调用身份受理，写出应答后交给执行队列，终态随调用身份及请求编号查询 | `request.rs`、`control/outcomes.rs` |

## 计划与转换

设 $C$ 为基础配置，$U$ 为已授权的修改，$M$ 为固定产物的组件声明。规范化函数 $N(C,U,M)$ 返回确定的目标 $D$ 或带来源的校验错误。授权以管理服务绑定及基础配置为据。作用域控制服务解析，分组控制进程位置与故障范围。对健康、稳定且产物身份相同的运行状态，$\operatorname{plan}(D,D,R,\varnothing)=\varnothing$；显式重启、宿主故障与停机各有独立意图。

固定计划输入后，以直接变化的实例为 $A_0$。从 $A_i$ 沿实际绑定查找消费者，沿父子关系查找随父撤回的实例，并在进程重启时加入同一故障域的成员，得到 $A_{i+1}$。候选提供方还须纳入原来等待该接口且作用域相同的消费者。有限实例集 $I$ 上至多有 $|I|$ 次严格扩张。范围外且解析结果稳定的实例保留其运行纪元。对动态子实例，准备阶段需涵盖可能随候选变化的既有实例；发布之前验证其归属。

操作依次准备产物、捕获原状态、激活候选和确认。确认结束时，操作仍持有旧实现与交接状态。持久决定有三种结果：

| 决定 | 后续转换 |
|---|---|
| `NotCommitted` | 同一操作恢复旧定义、身份和状态，解冻原导出器，释放候选。恢复失败时记录实际受损范围 |
| `Committed` | 发布已接纳目标，退役旧租约并回收暂存目录。清理失败附于该决定 |
| `RecoveryRequired` | 暂停新的结构写入、确认来源写入和检查点覆盖，根据磁盘日志恢复确定版本 |

实现到规格的映射 $\alpha$ 把持久日志指向的配置解释为 $D_c$，把内核目录与连接快照解释为 $R$，把冻结状态和磁盘检查点解释为 $P$。合法步骤要么改变一个已说明的模型状态，要么在固定观察时点保持公开结果。对同一快照 $x$，字段 $y=f(x)$ 可以由读者求得；删除其独立写入保持 $(x,f(x))\leftrightarrow x$ 的一一对应。版本缓存的生存期由 $x$ 的所有者决定。

## 调用与效应的寿命

令 $g$ 为消费者运行纪元，$k$ 为服务键，$b_g(k)$ 为该纪元接纳的提供方绑定。调用使用 $b_g(k)$ 的具体对象。即使提供方名称和版本再次相同，旧连接关闭后发来的结果仍属于旧请求。连接编号和方向确定请求编号的作用域，应答表中相应条目的移除决定唯一终态。发送前放弃请求时，参数引用由本地拥有者释放；写出后取消请求时，释放责任随载荷和远端应答处理。已有的代际及资源契约分别见[组件行为规格](01-semantics.md)和[传输协议](16-up1-protocol.md)。

设本地单调钟读数为 $t$，父调用截止时刻为 $d_p$，本跳可用时长为 $b$。嵌套调用的截止为 $d=\min(d_p,t+b)$。进入传输队列和等待队列容量都会消耗这段时间。UP/1 对端协商支持传播时，发送方在出站路径换算剩余时长，接收方用自己的单调钟建立本地截止。原发送方持续执行其截止和取消。Rust 原生任务继承调用的时间上下文，Python 和 Node 分别绑定到当前任务与调用信号。旧连接及浏览器按既有取消契约运行。原生调用对外结束与内部同步函数实际退出是两个时点，源库租约覆盖内部执行和析构。

把框架控制的资源记为 $\Gamma$。效应 $e$ 在状态 $x$ 上成功登记后，给出新状态 $x'$ 和本次登记的清理操作 $u$。清理令牌归登记者，消费令牌后执行 $u(x')\approx x$，等价关系比较仍然活跃的服务、任务、监听器和后续调用行为。业务存储由提供业务服务的组件决定提交时点。部署操作交还冻结令牌、连接归还出口引用和库释放描述符，分别由各自的资源所有者完成。

## 验收

| 性质 | 观察与实现验证 |
|---|---|
| 公开绑定、效应的唯一释放和代际隔离 | 上游 177 项适用分类与 Rust 内核一致性测试；保持依赖方先清理及锁外析构 |
| 配置幂等、故障局部性、页面继承 | 通过管理接口执行同声明重载、A→B→A 和提供方更换，核对受影响实例、页面草稿和范围外的原加载代 |
| 持久决定 | 在写入、移动日志、目录同步与决定后清理的切点，比较在线状态、离线来源及重新启动后的实际值 |
| 状态与租约 | 首次写入后立即 SIGTERM、1 MiB 与 4 MiB 状态继承、长调用中热替换；以返回值、析构完成及关闭结果为据 |
| 构建与性能 | 用同一锁文件、平台、编译器和 release 参数重建基线和候选；分开记录生产、测试、生成代码及构建工具 |

每个场景先探索一次，再按次序交替测十组配对样本。macOS 记录各进程 RSS、线程和 physical footprint，Linux 记录 RSS、线程和 PSS。空核心、单个及多个 KV、三个库共享与分组、持续热替换、慢导出和同组短调用分别观察。吞吐下降与 p99 或停顿上升的验收带均为 5%；波动超过此带时保留原始观测，标记待确认。ABI 主版本的独立工作区互操作、极短调用与资源传递分别验收。
