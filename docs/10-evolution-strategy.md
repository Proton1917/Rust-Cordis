# 插件独立演化与运行时交付

一次插件更新应由发布它的团队独立完成。使用方按接口取得服务，运行时决定何时切换，新提供方接手事务开始时导出的状态。无关实例继续使用原来的绑定。这样的替换能力要求稳定的业务接口、明确的资源寿命和按实例保存的部署来源。

## 三项分别演进的约定

| 使用者 | 约定 | 改动的影响 |
|---|---|---|
| 业务插件与调用方 | 接口名、版本、方法、数据、行为和错误 | 新实现对旧调用方履行同一契约；行为变化通过接口主版本表达 |
| 原生插件与宿主 | 库的入口、调用与完成、字节和资源句柄的归属 | 新一代宿主应识别已安装插件的 ABI 主版本并找到相应执行环境 |
| 数据所有者与后继实例 | 状态模式、版本、已提交操作的身份 | 提供方负责解释旧状态、查询已提交结果和迁移持久数据 |

接口采用 WIT 时，三种语言的绑定从同一声明生成。Rust 插件可在自身库内使用常规类型与直接函数调用；公开方法的声明顺序属于源码组织。[接口与版本](11-plugin-model.md) · [调用设计](12-abi-v1.md)

## 同一应用中的插件

插件数来自业务拆分，宿主数来自应用愿意共同重启的范围。目标部署中，常规原生插件共享宿主。应用有独立恢复要求时显式配置其他组。核心拥有实例图和实际调用来源；HTTP、密钥、业务状态和长任务各归相应插件。网页在浏览器中运行，经 HTTP 插件连接核心。[部署模型](15-universal-socket.md)

## 版本过渡

v0.2.5 的应用继续按原分组、原生 ABI 和既有配置装配。新部署格式显式选择共享默认值；旧安装中的已确认程序引用仍按旧语义读取。新旧原生库通过相应版本的宿主连接同一内核，业务服务依接口版本绑定。应用可以先迁移一个提供方，再迁移消费者。现行 ABI 兼容期见 [ADR-0014](adr/0014-versioning.md)。

## 性能评价

比较同宿主调用、跨宿主调用和真实业务操作，从调用方发起到结果消费完成计时。进程数、线程数和物理内存足迹在相同插件与负载下采样。旧版本的直接调用纳秒基准与跨进程微秒基准各有独立计时边界；新设计的分派与编码开销有待实现测量。[历史性能样本](measurements/m21-performance/README.md)
