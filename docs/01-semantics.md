## 第一部分 理论条款

### 1.1 可回退效应（`PAPER` §3.1、§3.3.1、§3.3.2、§4.1.1）

效应函数的类型是 `Γ → Γ × (Γ → Γ)`：作用于上下文，交回新的上下文和本次变换的逆函数（定义 6）。

| 条款 | 内容 | 出处 |
|---|---|---|
| `T-EFF-1` | `effect(callback)` 执行回调，把回调交回的逆变换登记到所属上下文的累积逆变换中，并向调用方返回一个释放函数。累积采用前置复合：后登记的逆变换先执行（后进先出） | 定义 7，算法 1 第 17 行 |
| `T-EFF-2` | 每个释放函数至多生效一次。每次 `effect` 调用生成一个私有的待命标志；第二次调用释放函数不产生任何作用 | 定义 21，算法 1 第 10–14 行 |
| `T-EFF-3` | 回调可以是效应迭代器：分多步执行，每一步交回一个逆变换。各步的逆变换按后进先出顺序复合 | 定义 22、23 |
| `T-EFF-4` | 迭代器的每个步骤边界是中断点。执行每一步之前检查守卫；守卫失效时停止迭代，只保留已累积的逆变换。单步效应是迭代器的退化情形，不含中断点 | §3.3.2，算法 1 第 4–7 行 |
| `T-EFF-5` | 释放函数会终止仍在进行的迭代（把待命标志置假使守卫失效），等待执行任务结束，再应用累积的逆变换 | 算法 1 第 12–16 行 |
| `T-EFF-6` | 子效应的释放函数本身是父上下文上的一个效应。释放父效应即按相反顺序释放它聚合的子效应 | 定理 11，§4.1.1 “父上下文组合” |
| `T-EFF-7` | 模型只覆盖系统能完全控制的内部上下文状态。网络请求、文件 I/O 等外部交互由组件在逆变换中自行补偿 | §3.1.1 |

### 1.2 反应式余效应（`PAPER` §3.2、§4.1.2）

余效应上下文是依赖键到带类型值的有限偏函数 `Σ := (k : K) ⇀ V_k`（定义 12）。

| 条款 | 内容 | 出处 |
|---|---|---|
| `T-COE-1` | `get(k)` 返回当前绑定的值。类型族 `V` 保证键 `k` 的值具有类型 `V_k` | 定义 13 |
| `T-COE-2` | `set(k, v)` 是一个效应函数：建立绑定，交回的逆变换移除该绑定。前置条件是 `k ∉ dom(σ)`，同一个键在同一隔离域内不能被提供两次 | 定义 13，算法 2 |
| `T-COE-3` | 建立绑定和移除绑定时都调用 `notify`，把变化传播给依赖该键的组件 | 算法 2 第 8、11 行 |
| `T-COE-4` | 组件的余效应规格 `d` 是它声明的依赖键集合。满足谓词 `σ ⊨ d` 当且仅当 `d` 的每个键都在 `dom(σ)` 中 | 定义 14，式 (9) |
| `T-COE-5` | 每次 `σ → σ'` 的变化按规格 `d` 分类：`σ ⊭ d ∧ σ' ⊨ d` 为激活型，`σ ⊨ d ∧ σ' ⊭ d` 为停用型，其余为中性。激活型触发组件效应的执行，停用型触发已累积效应的恢复 | 定义 15 |
| `T-COE-6` | 依赖顺序由通知机制推出，不需要另行指定：依赖方在提供方完全激活并提供键之后才激活；提供方开始恢复之前，依赖方已完全停用 | §3.2.2 末段 |
| `T-COE-7` | 隔离：上下文携带隔离域表 `ρ : K → R` 和按域标识符索引的依赖表 `σ : R ⇀ V`。`get(k)` 先解析 `ρ(k)` 再取 `σ(ρ(k))`。`isolate(k, r)` 派生一个把 `k` 映射到域 `r` 的子上下文；不指定 `r` 时使用新生成的域 | 定义 16、17，§4.1.2 |
| `T-COE-8` | 同一个键在两个被指派不同域的上下文中解析到彼此独立的绑定；被指派同一个域标识符的上下文共享绑定 | §3.2.3 |
| `T-COE-9` | 拦截：每个键 `k` 有元数据类型 `M_k`，带有满足结合律的合并操作 `⊕_k` 和单位元 `ε_k`。上下文携带元数据表 `ι`，规格可为每个键声明元数据 `d(k)` | 定义 18 |
| `T-COE-10` | 规格为 `d` 的组件访问键 `k` 时，提供方看到的元数据是 `d(k) ⊕_k ι(k)`。合并是右偏的，上下文携带的 `ι(k)` 优先于组件声明的 `d(k)` | 定义 19 |
| `T-COE-11` | `intercept(k, ν)` 派生子上下文，其元数据为 `ι(k) ⊕_k ν`，新元数据优先于已有元数据 | 定义 19 |
| `T-COE-12` | 拦截只改变依赖的使用方式，不改变依赖是否满足。安装、调整、移除拦截不触发组件重新加载 | §5.2，术语表 A.3 |
| `T-COE-13` | 隔离与拦截采用派生实现：派生子上下文，父上下文不变，恢复即丢弃子上下文，不需要显式逆变换 | 定义 25，§4.1.2 |

### 1.3 组件生命周期（`PAPER` §3.3、§4.1.3）

组件是二元组 `(d, e)`：余效应规格 `d` 与效应函数 `e`（定义 20）。纤程是组件的运行时实例。

| 条款 | 内容 | 出处 |
|---|---|---|
| `T-LIF-1` | 目标状态为 `ACTIVE` 当且仅当两个条件同时成立：组件存活（效应已应用且未被释放）；`σ ⊨ d`。否则为 `INACTIVE` | 定义 20 后的说明 |
| `T-LIF-2` | 纪元 `ε_d(σ) := ⟨σ(k) | k ∈ d⟩`。两个纪元相等当且仅当所有依赖值相同。`INACTIVE` 的纪元是特殊常量 `⊥`，不等于任何活跃纪元 | 式 (17) |
| `T-LIF-3` | `refresh(fiber)`：计算纪元；与 `fiber.epoch` 相同则返回；否则写入 `fiber.epoch`；若已有在途迁移则返回；否则纪元非 `⊥` 时启动 `reload`，为 `⊥` 时启动 `unload` | 算法 5 第 1–9 行 |
| `T-LIF-4` | `reload(fiber)`：记录开始时的纪元 `epoch₀`；以“当前纪元仍等于 `epoch₀`”为守卫执行组件的效应函数；把得到的逆变换前置到 `fiber.dispose`；结束时纪元仍为 `epoch₀` 则清除在途迁移，否则串联进入 `unload` | 算法 5 第 10–17 行 |
| `T-LIF-5` | `unload(fiber)`：执行 `fiber.dispose` 并把它重置为恒等；结束时纪元为 `⊥` 则清除在途迁移，否则串联进入 `reload` | 算法 5 第 18–24 行 |
| `T-LIF-6` | 惯性：迁移一旦开始即运行至完成。目标状态在迁移期间的变化只修改 `fiber.epoch`，由迁移结束时的检查处理 | §3.3.4 |
| `T-LIF-7` | 两个层次的纪元检查同时存在：迁移结束时的检查支持跨迁移的串联；迁移内部每个迭代器步骤边界的检查支持单次迁移内的部分回滚 | §4.1.3 末段 |
| `T-LIF-8` | 组件实例化是父纤程上的一次效应。效应体调用 `refresh(fiber)`；逆变换把子纤程的纪元置为 `⊥` 并触发 `unload`。卸载父组件因此级联到所有子组件 | 算法 4 |
| `T-LIF-9` | `fiber.ctx` 由 `fiber.parent` 派生，供该纤程在其中运行；纤程按上下文层级构成一棵树 | §4.1，算法 4 第 8 行 |
| `T-LIF-10` | 依赖环使环上的组件保持非活跃。这种状态可以静态预测，不产生运行时错误 | §5.4 |

### 1.4 上下文访问（`PAPER` §3.4、§4.1.4、§5.2）

| 条款 | 内容 | 出处 |
|---|---|---|
| `T-CTX-1` | 效应与余效应经由同一个显式的一等上下文发生。每个操作可归属于调用它的上下文，进而归属于该上下文所属的组件 | 定义 24，§3.4.2 |
| `T-CTX-2` | 经上下文中介的访问强制执行余效应规格：从发起访问的上下文沿纤程链向上遍历，遇到第一个在 `inject` 中声明了该键的纤程时访问获得授权；到达根仍未发现声明则拒绝访问 | 算法 6 |
| `T-CTX-3` | 获得授权的访问不会遇到“已声明但不存在”的值，因为纤程只有在全部已声明余效应满足后才进入 `ACTIVE` | §4.1.4 |
| `T-CTX-4` | 依赖声明充当能力请求，上下文充当能力中介。组件所需的全部能力在其运行前已知 | §5.2 |

## 第二部分 实现条款

本部分按 `UPSTREAM` 源文件组织。每个文件一节，先给出对象定义，再列条款。

### 2.1 Context（`context.ts`）

上下文是一条视图链。根上下文持有全部内核状态；每个派生上下文继承父上下文的全部属性，并覆盖其中若干项。链上可被覆盖的项有三个：所属纤程 `fiber`、隔离域表 `@@isolate`、拦截表 `@@intercept`。

| 条款 | 内容 | 源码 |
|---|---|---|
| `S-CTX-1` | 构造根上下文时依次创建根纤程和四个核心服务 `reflect`、`registry`、`events`、`logger`，随后清空根纤程的效应列表。核心服务自身登记的效应因此不随根纤程重启而释放 | `context.ts:36-48` |
| `S-CTX-2` | `extend(meta)` 派生子上下文，`meta` 的属性覆盖继承值 | `context.ts:55-63` |
| `S-CTX-3` | `isolate(name, label?)` 派生子上下文，其隔离域表在 `name` 上映射到 `label`；未给出 `label` 时使用新生成的域。其他键的映射继承自父上下文 | `context.ts:65-69` |
| `S-CTX-4` | `intercept(name, config)` 派生子上下文，其拦截表在 `name` 上增加一层 `config`。各层保留，在访问时合并（`S-SVC-9`） | `context.ts:73-77` |
| `S-CTX-5` | 键 `name` 第一次被提供时，根隔离域表为它登记一个默认域。未经 `isolate` 的上下文都解析到这个默认域 | `reflect.ts:222` |

## 第三部分 `PAPER` 与 `UPSTREAM` 的差异

`UPSTREAM` 在 `PAPER` 的算法之上增加了以下细节。Rust 实现采纳 `UPSTREAM` 的做法。

| 编号 | `PAPER` | `UPSTREAM` | 相关条款 |
|---|---|---|---|
| `D-1` | 算法 5 只有 `INACTIVE`、`ACTIVE` 与两个惯性状态 | 增加 `FAILED` 与 `DISPOSED`；失败的纤程不随依赖变化重试 | `S-FBR-1`、`S-FBR-7` |
| `D-2` | 纪元是依赖值的元组 | 纪元是修订号加各绑定的 `uid`。修订号使依赖不变时的 `restart` 也改变纪元 | `S-FBR-5`、`S-FBR-18` |
| `D-3` | 算法 6：到达根仍未发现声明则拒绝 | 祖先纤程自己提供的服务无需声明即可访问；以根为定义点的访问不做检查 | `S-SVC-6`、`S-SVC-8` |
| `D-4` | `get` 读取当前存储 | 获得授权的访问读取纤程加载开始时的已提交视图 | `S-SVC-9` |
| `D-5` | 依赖顺序由 `notify` 推出 | 另有显式的依赖方集合：提供方的 `_unload` 与绑定的撤回都等待依赖方清理完毕 | `S-FBR-12`、`S-SVC-2` |
| `D-6` | `unload` 整体执行 `fiber.dispose`，按后进先出顺序 | 顶层效应按相反顺序启动、并发执行；单个效应内部严格后进先出 | `S-FBR-12`、`S-EFF-3` |
| `D-7` | 绑定存在即满足 | 绑定还要求提供方纤程为 `ACTIVE` 且可用性谓词通过 | `S-SVC-3`、`S-SVC-4` |
