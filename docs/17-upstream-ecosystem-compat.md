# 原版 Cordis 的参照范围

Rust-cordis 以原版 TypeScript Cordis 的组件组合行为为参照。一个组件声明依赖，通过上下文登记效应，随服务出现而激活，随依赖撤回而清理；多实例可以共享同一个执行环境。Rust 内核以类型化键、句柄和 Future 表达这种行为。[上游行为对照](04-conformance.md)

## 组件语义与语言实现

JS 插件可以持有闭包、读取代理属性、依赖 this 绑定或使用模块缓存。现行 TypeScript SDK 面向 UP/1 进程插件；用原版 Cordis API 编写的 npm 包有另一套宿主约定。支持这类包原样运行，需要 Node 承担模块解析及同步语言语义，核心仍唯一管理实例、依赖和生命周期。

## 已提出的兼容方案

DOC-17 的历史方案把 JS 语言对象放在 Node 宿主，通过受约束的同步桥与 Rust 内核交换生命周期事实。C0–C4 是该专项的历史实施划分，当前处于待排期状态。兼容判断应从真实上游插件开始，观察装载、拦截、依赖撤回与更新的顺序，并保留要求同步完成的 JS 行为。[兼容宿主决策](adr/0050-upstream-compat-host.md)

共享原生宿主与固定原生分派可以独立设计和交付。原版源码兼容专项的单独目标是让仍使用 JS 对象、模块与原版 API 的插件获得匹配的执行环境。
