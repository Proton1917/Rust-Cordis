# ADR-0050 以兼容宿主承接原版 cordis 插件生态

| 项 | 内容 |
|---|---|
| 状态 | 已提议，未排期（设计方 2026-11-14）。设计全文见 `DOC-17`；实施从 `DOC-17` §10 的 `C0`、`C1` 开始，`C1` 关口通过后由项目所有者决定是否继续 |
| 影响 | 新增 `compat/`（兼容包、Node 兼容宿主、档案）、`tools/compat/`；`crates/cordis-supervisor` 的动态组件与同步控制请求；`DOC-16` 新增 `compat-js/1` 能力 |
| 预计不影响 | 内核 `crates/cordis`、`cordis-abi` 与 ABI v1、已发布 SDK 的协议行为 |

## 1 问题

项目所有者要求 Rust-cordis 兼容原版 cordis 插件生态（2026-11-14 总方针）：原版插件不改源码，由 Rust-cordis 装载和管理。

现有设计中有三处限制，原版插件无法直接运行：

1. 组件只能来自已登记的插件描述符（`DOC-16` §13）。原版插件在运行时以函数、构造器或对象调用 `ctx.use()`，组件是闭包。
2. 宿主的状态变更都是异步请求，`effect` 的效应体还要由核心回调宿主执行（`DOC-16` §8）。原版要求 `ctx.set` 后立即 `ctx.get`、`ctx.effect` 同步执行效应体、`ctx.on` 后立即派发。
3. 远端事件只是通知（`DOC-15` §6.3）。原版的 `bail`、`waterfall` 需要同步取回监听器的返回值。

## 2 职责放置

逐项依据 `AGENTS.md`“第一性原理”，完整裁决表见 `DOC-17` §2.1。

| 能力 | 唯一掌握事实者 | 放置 | 理由 |
|---|---|---|---|
| 组件实例、依赖绑定、纪元、状态迁移、效应顺序 | 内核 | 不变 | 第 2 条：只有一个内核。兼容宿主只保存投影，任何状态迁移都由内核回执决定（`DOC-17` `SC-1`） |
| 闭包、函数身份、属性代理、`this`、语言判定（`check`、配置校验、事件 `filter`） | Node 兼容宿主 | 宿主 | 第 4、6 条：语言语义归终结它的一方；核心不运行插件代码（`Q0`） |
| 模块解析、配置组装、HMR | 上游 loader、include、group、hmr 插件 | 原样运行于宿主 | 第 3 条：它们本来就是 cordis 插件，只依赖 `cordis` 公开接口 |
| 同步控制请求与增量回执、动态组件登记 | `UP/1` 两端与监管器 | 新能力 `compat-js/1` | 第 5 条：复用实例、上下文、效应、对象编号与资源规则，只在协商后启用 |

内核不增加职责。监管器以内核已有的 `ComponentDef::new` 构造动态组件，加载函数向宿主下发执行请求。`C1` 核实内核无需改动；若需要，先写出只有内核掌握相关事实的证明，交设计方确认。

## 3 决定

1. 新增 Node 兼容宿主作为进程插件。一个宿主进程是一个执行分组，原版应用的插件运行在同一分组中，保持同步调用与对象身份。
2. 新增兼容包 `cordis`，导出与上游 4.0.0-rc.12 相同。处理语言事实的上游源码原文复用（MIT 许可，保留版权声明）；服务表、状态机、组件登记改为调用宿主运行时，由内核决定。
3. 宿主通过同步桥向核心发出同步控制请求：通信线程独占标准输入输出，执行线程以 `Atomics.wait` 等待回执。回执携带内核按提交顺序产生的全部相关增量，宿主在返回调用方前应用；回执中的加载按上游时序在微任务中执行（`DOC-17` `SC-2`–`SC-5`）。
4. 核心处理同步控制请求时不等待任何宿主（`DOC-17` `SC-6`）。语言判定采用两段提交（`DOC-17` §4.4）。
5. 同分组事件在宿主本地按上游语义派发。跨分组事件保持 `DOC-15` §6.3 的通知语义，`J1` 不扩展；跨分组带返回值的派发另写 ADR。
6. 上游服务名映射为内核键 `<档案>/<根编号>:<名称>`，跨语言可见需要显式导出或导入声明（`DOC-17` §5.2）。
7. 兼容承诺按档案记录；首个档案 `J1` 对应上游 `261c5fd`，运行环境为 Node.js。浏览器端原版插件与 cordis 3.x 不在 `J1` 范围内。
8. 协议新增内容在 `hello` 中以能力 `compat-js/1` 协商，未协商的连接行为不变。

## 4 验收

见 `DOC-17` §9（`CX-1`–`CX-10`）。关口为 `CX-1`：同步纵向原型在上游参考环境与兼容环境中结果逐项相同，`SC-6` 下无死锁，同步往返数据已记录。

## 5 后果

1. 原版插件生态与 Rust、Python、TypeScript 插件共用同一个内核、同一套依赖与生命周期。原版应用可以逐步把服务拆到其他分组或其他语言。
2. 原版应用的同步语义限定在一个分组内。跨分组只有异步契约，这一点写入档案的已知差异与 guide。
3. 兼容包跟随上游版本。上游 4.0 仍是预发布版，新版本以新档案纳入，旧档案保持可复现。
4. 同步往返增加原版应用的启动开销，`C1` 实测后由项目所有者确定预算。
