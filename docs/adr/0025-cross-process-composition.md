# ADR-0025 隔离域、拦截与组合经 `UP/1` 提供给插件

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | `DOC-15` §6.4、§8 第 3 条、§14、§15（`M11`、`M12`、`M14`、`M18`、`M19`）、§16（`AU-18`）、§17（`D-13`）；`docs/16-up1-protocol.md`；`DOC-12` `HostV1`；`DOC-13` SDK 草图；`DOC-11` §10 |

## 问题

内核实现了论文的空间组合能力：`isolate`（`T-COE-7`、`S-CTX-3`）、`intercept`（`T-COE-11`、`S-CTX-4`、`S-SVC-9`），以及组件在派生上下文中装入子组件。`Q0` 之后插件只经 `UP/1` 与内核交互，而 `UP/1`、ABI v1 与 Rust SDK 都没有提供这三项能力：插件不能建立隔离域、不能声明拦截、不能装入子组件，提供方也读不到调用方范围内的拦截元数据。内核中的这部分实现在核心程序里无从调用，系统失去了论文范式中的空间组合。

## 选项

### 拦截元数据如何送达提供方

| 选项 | 内容 | 代价 |
|---|---|---|
| A1 | `invoke` 增加元数据参数 | 改变 ABI 对象入口签名；同组直接调用的类型化方法表也要改；`M11` 前要大改 ABI |
| A2 | 每次调用由核心查询并附带元数据 | 同组直接调用不经过核心，无法附带 |
| A3 | 按句柄绑定：提供方声明 `scoped`，核心在 `get` 时经通用调用 `cordis.scope(meta)` 取得绑定了元数据的视图对象交给使用方 | 每个（使用方上下文，绑定）多一个视图对象 |

### 插件如何使用隔离域与组合

| 选项 | 内容 | 代价 |
|---|---|---|
| B1 | 只在 `cordis.toml` 中声明 | 插件内部无法组合子组件 |
| B2 | 部署层在 `cordis.toml` 中声明；插件层增加 `context_derive` 与 `plugin` 两条请求 | `HostV1` 追加两个槽位 |

## 判据

1. 论文的空间组合能力对任何插口上的插件都可用。
2. 同组原生插件之间的直接调用不退化（`AU-9`）。
3. ABI v1 冻结前完成，冻结后不需要修改对象布局。
4. 实例、域、拦截的决定仍只由核心中的唯一内核作出。

## 决定

选 A3 与 B2。

- `cordis.toml` 实例条目增加 `isolate`（域名字符串或 `true`）与 `intercept`；核心创建实例上下文时应用。
- `UP/1` 增加 `context_derive`（派生带隔离域与拦截的上下文）与 `plugin`（在给定上下文中装入调用方插件自己的组件，作为调用方的效应）。装入其他插件的组件经 `cordis.toml` 或 `cordis.manage@1`。
- `provide` 增加 `scoped`。核心在使用方上下文对该接口的合并元数据非空且提供方为 `scoped` 时，经 `invoke(provider, "cordis.scope", [meta])` 取得视图对象返回给使用方，并按（使用方上下文，绑定）缓存。
- `HostV1` 在 `M11` 冻结前追加 `context_derive`、`plugin` 槽位；原生、Python、TypeScript SDK 提供 `isolate`、`intercept`、`plugin` 与 `Scoped` 提供方辅助。
- `bail`、`waterfall` 维持只用于核心内部（`DOC-15` §6.3）。

## 后果

- `M11` 实现核心、`UP/1`、宿主函数与原生 SDK 部分，`M12` 实现 `cordis.toml` 部分，`M18`、`M19` 实现脚本语言 SDK 部分；`AU-18` 在 `M14` 验收。
- 浏览器页面的独立域（`DOC-15` §11.2）使用同一机制。
- 视图对象与原对象位于同一宿主，同组原生使用方仍直接调用。
