# ADR-0048 HTTP 脚手架与密钥文件打包职责

| 项 | 内容 |
|---|---|
| 状态 | M22 实施决定，随里程碑复核 |
| 影响 | DOC-13 §1.1；cordis-dev 的脚手架与发布打包 |

## 职责与现状

ADR-0046 增加三语言 HTTP 处理方脚手架，并要求发布包排除密钥文件。两项操作都发生在开发工具中：脚手架负责生成文件和项目配置，打包器掌握实际装配条目及复制清单。核心通过现有命令转交调用 cordis-dev。

M21 的 cordis-dev 为 2308 代码行。M22 在复用现有部署目录、Rust 依赖来源、WIT 生成器与 skill 模板后为 2577 代码行，超过原 2500 行上限。新增代码主要是 HTTP 三语言源码生成、打包时读取密钥提供方描述符和排除配置文件，以及 SDK 新模块的嵌入清单。

## 方案与决定

| 方案 | 职责与维护影响 |
|---|---|
| 保留 cordis-dev 的现有模块边界 | HTTP 生成器复用 process 脚手架；密钥文件识别接入 pack 的描述符读取，复制阶段共用排除清单 |
| 提取脚手架或 pack 为独立 crate | 可以独立复用与发布，需要把命令配置、错误类型、路径和源码嵌入接口跨 crate 暴露 |

采用现有模块边界，目标保持 1500 行，上限调整为 3000 代码行。当前使用者为同一个 cordis-dev 命令入口，按职责维护 scaffold/http.rs 和 pack/secrets.rs 即可表达两项能力。未来独立使用者出现时，沿完整的脚手架或打包职责提取。

代码行与总行按 tools/source_lines.py 分别记录。HTTP 模板直接引用 skill 的维护源，Python 与 TypeScript 的协议绑定由现有 WIT 生成器产生；密钥文件依据原生插件的实际服务声明识别，描述符查询结果供后续打包装配复用。

## 验证

三语言生成项目完成真实构建及 HTTP 请求。密钥场景同时验证文件权限、实例授权、服务环境变量与实际 tar 内容。工作区检查覆盖原有脚手架和发布场景，结果写入 PROGRESS 的 M22 节。
