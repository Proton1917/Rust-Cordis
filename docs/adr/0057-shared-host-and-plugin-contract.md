# ADR-0057 共享宿主、稳定方法身份与应用交付

本决定记录下一版的设计。现行发行版为 v0.2.5，主分支的 ABI 1.2 仍属于 v1 系列。新分组和新调用入口都需要在部署清单中明确版本后实施。

## 决策依据

组件可以独立挂载、替换和卸载，这些行为由上下文、依赖和效应保证。原生插件可以独立编译，但同一进程内执行的原生代码共用地址空间。旧方法表让两个独立构建的业务接口还需约定函数位置和机器签名。已有故障记录显示，一致的接口主版本仍可能对应不同的方法布局。[方法表回归](0056-typed-layout-digest.md)

现行打包入口以部署目录寻找 Cargo 工作区，二者分开时，应用常需先定位真正的编译产物再装配。运行时才掌握的最后确认程序绑定也曾需要下游读取私有文件。公开的离线查询已经解决后一个问题。[构建职责](../13-runtime-architecture.md) · [程序绑定查询](0054-offline-source-query.md)

## 决定与适用条件

1. 新部署按原版组件模型隔离实例，常规原生插件共享宿主。显式分组表达独立承受进程故障的要求。旧清单按照原有分组解释。
2. 原生插件保留独立编译、类型化 SDK 和本地调用。宿主与动态库之间的机器入口固定，业务方法按稳定身份分派。绑定时判断契约相容性；换版本后原绑定随加载代退役。
3. 将业务提交与结果传输分别表达。普通调用可以返回小值；已提交操作返回稳定回执，大对象通过快照、分页或流读取。解释业务提交状态的职责属于数据所有者。
4. 官方工具接受源码工作区和部署输入，输出可启动的完整程序包。应用负责业务源代码、依赖与资源声明；框架负责宿主匹配、平台产物定位、签名及装配。

## 权衡与迁移

同宿主可以省去跨进程往返及重复的宿主资源，同组的进程级崩溃会中断所有成员。新分派入口把声明变化限制在业务绑定中，代价是编码、解码与一次固定入口分派。旧版的纳秒级直接调用测量描述的是旧方法表。新实现的延迟、峰值内存和恢复范围取决于真实插件与数据。

旧 ABI 主版本在承诺的支持期内由相应宿主接纳；新增入口使用新的主版本。部署解析先识别格式，再应用分组规则。升级时核对应用先前保存的程序绑定和业务快照。实施与验收次序见[交付验收](../14-roadmap-phase2.md)。
