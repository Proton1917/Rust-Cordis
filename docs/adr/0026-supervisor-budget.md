# ADR-0026 统一核心监管器的模块上限

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | DOC-13 §1.1；M10 核心监管与 M11 的组合接口 |

## 问题

Q0 将全部生命周期决策集中到核心监管器。该模块负责远端定义与上下文、服务路由、效应与清理、状态导出、替换回滚、进程故障恢复，以及调用者取消等待后的事务执行。CP 的输入与保留资源约束增加了独立额度管理。M10 正常格式化后的 supervisor src 为 3580 行，原上限为 3500 行。

ADR-0025 已确定后续在同一上下文和路由模型上提供隔离、拦截与子组件组合。进程退出还需统一组信号与子进程回收的执行责任。

## 选项与判据

保持生命周期、路由和状态迁移在同一 crate 内，内部按 generation、handlers、lifecycle、metadata、model、routing 和 process 分模块。拆分 crate 会增加共享事务和上下文所有权的内部接口，职责边界仍然需要相同的协调。

## 决定

cordis-supervisor 的目标设为 3500 代码行，上限设为 4500 代码行。按项目所有者在 M11 的要求，空行、普通注释与文档注释从上限计量中排除，PROGRESS 同时报代码行与总行；M10 的 3580 行记录为当时的总行数。内核继续保持 6000 代码行上限，ABI、宿主及其他 crate 使用 DOC-13 §1.1 的相同计量方法。

## 后果

核心监管的状态与所有权有一个实现来源，保持标准 Rust 格式、完整条款注释和明确的模块职责。约 60 行以上的函数按步骤拆分，通过去重和职责调整后仍超过 4500 代码行时写 ADR，继续工作，由设计方复核。
