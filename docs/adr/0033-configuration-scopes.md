# ADR-0033 配置分组与上下文继承

| 项 | 内容 |
|---|---|
| 状态 | 已采用，随 M12 复核 |
| 依据 | UPSTREAM-EXT `loader/src/config/{entry,group,tree,isolate,utils}.ts`；DOC-15 §4、§6.4 |
| 影响 | DOC-11 §10、运行时配置与增量调和 |

## 问题

上游的 `group = true` 表示包含子条目的逻辑配置组，组的禁用状态、隔离域与拦截元数据由子条目继承。DOC-15 已用实例的 `group` 字符串选择原生宿主进程，需要同时表达这两种关系。

## 选项与判据

可以让同一个 group 字段同时接受宿主名称和逻辑组定义，或分别命名。分别命名使宿主部署与上下文继承保持独立，配置差异可以直接映射到现有内核视图。

## 决定

- 顶层 `[scope.<名称>]` 声明逻辑配置组，字段为 `parent`、`disabled`、`isolate`、`intercept`；实例通过 `scope` 选择所属组。实例的 `group` 继续选择宿主进程。
- 组和实例的 `disabled` 为布尔值；任一祖先禁用时，其成员从运行目标中移出，配置条目保留。重新启用后按已有描述符和配置挂载。配置组的环和缺失父组在配置解析阶段报告，继承深度沿 CP-8 使用 64 层上限。
- 隔离域和拦截逐层继承，最近一层覆盖相同键。拦截元数据的表字段使用浅合并，与 DOC-15 §6.4 的内核操作一致。组内 `isolate = true` 由组拥有内部域名称，使子条目共享该组的域；实例自身的 `true` 保持独有域。
- 内部组域使用以 `\0cordis.scope/` 开头的名称空间，人维护的配置使用其余名称。组名称保持稳定时，未变成员沿原视图继续运行；受影响成员由现有增量调和重建。
- 配置解析使用 TOML，条目以表名保持稳定身份。JavaScript 表达式及 Node 模块解析由 Q0 与 Rust 部署形式改为数据配置和插件描述符；部署依赖取自插件声明。
- `Configuration::effective` 在叠加层之后展开配置组，产生平铺的运行目标。展开后的配置按 CP-2 限定总体容量，避免继承导致无界放大；管理授权仍取自基础实例的 grants。

## 后果

上游的组禁用、隔离共享和拦截继承通过现有 Rust 内核能力实现。宿主分组可以独立调整；配置组自身保存上下文参数，实例生命周期仍由核心内核管理。
