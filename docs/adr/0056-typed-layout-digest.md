# ADR-0056：类型化方法表的布局摘要

| 项 | 值 |
|---|---|
| 状态 | 已实现 |
| 日期 | 2026-11-16 |
| 依据 | DOC-12 §7、§7.2，DOC-11 §3 接口版本规则，ADR-0039 |
| 修订 | DOC-12 §7 对象首部 `flags`、`reserved` 的含义；ABI 次版本 1.2 |

## 问题

接口对象（`kind = 1`）在 `flags` 位 0 为 1 时提供类型化方法表。使用方的代理由 `#[interface]` 宏按**使用方自己编译时**的接口声明生成：第 i 个方法读取第 i 个槽位，并把槽中的函数指针按该声明转换成 C 函数类型后调用（`Object::typed_slot`）。

调用前的检查有两项：

1. `check_interface`：接口名与主版本相同。
2. `typed_slot`：槽位数量覆盖第 i 个槽。

两项检查都不验证“提供方第 i 个槽的函数签名与使用方的声明一致”。`typed_slot` 的安全前提写作“函数指针类型由接口宏的声明顺序保证”，这只在双方用同一份接口声明编译时成立。

以下任一情况会使前提失效，而上述两项检查都能通过：

- 开发中修改了接口方法，未修改版本号；
- 在已有方法之间插入新方法，只升级次版本；
- 方法的原始类型参数改变（如 `u64` 改为 `u32`）、参数个数改变、同步方法改为异步。

此时使用方以错误的函数类型调用提供方的函数，结果是未定义行为：参数被错误解释、返回槽被错误写入、栈或堆损坏，表现为随机崩溃或静默的数据错误。该情况只出现在同一原生分组内：跨分组调用经 UP/1 按方法名发送 CBOR，签名不一致时得到解码错误。

## 职责放置

“提供方方法表的 C 布局”只有编译提供方的宏知道；“使用方期望的 C 布局”只有编译使用方的宏知道。两者在运行时相遇的位置是使用方代理的调用点，比较只能在那里进行。数据由提供方的对象首部携带，核心与宿主只转交对象，不参与比较（`Q0`）。

## 选项

| 选项 | 内容 | 判断 |
|---|---|---|
| A | 维持现状，依赖版本号纪律 | 违反纪律的后果是未定义行为，且无法诊断 |
| B | 比较方法名表 | 能发现方法重排、插入、改名；不能发现同名方法的签名变化 |
| C | 宏为方法表计算布局摘要，使用方比较摘要，不一致时改用按名称的通用调用 | 采用 |
| D | 摘要不一致时拒绝调用 | 提供方只在末尾追加方法时，按名称调用仍然正确，拒绝会破坏兼容的升级 |

## 决定

### 摘要的内容

`#[interface]` 宏在编译期计算 32 位 FNV-1a 摘要，输入为按声明顺序排列的各方法的以下文本，以换行分隔：

1. 方法名；
2. 该方法槽位的 C 函数类型（宏生成的 `function_type()` 的 token 文本），其中包括各参数与返回值的线上类型、同步或异步形式。

用户定义的结构体在槽位中统一以 CBOR 字节（`AbiBuf`）传递，字段变化只会造成解码错误，不进入摘要。原始类型、参数个数、槽位顺序、同步与异步的差异都会改变摘要。

### 首部编码（ABI 1.2）

- `flags` 位 1（`OBJECT_TYPED_DIGEST`）为 1 时，`reserved` 存放布局摘要。
- 生成的接口对象（普通对象与 Scoped 对象）都设置位 1 并写入摘要。
- 位 1 为 0 的对象（旧 SDK 生成）`reserved` 仍为 0，含义不变。
- 读取方此前不检查 `reserved` 与位 1，旧使用方的行为不变。

### 使用方的调用规则

生成的代理在每次调用时：

- 提供方 `flags` 位 0 为 1、位 1 为 1，且摘要等于使用方的摘要：使用类型化槽位。
- 其他情况（提供方未带摘要、摘要不一致、提供方只有通用入口）：按方法名进入 `invoke` 或 `invoke_async`。DOC-12 §7 规定类型化对象同时提供通用入口，该路径始终可用。

按名称调用时，方法缺席返回 code 3，参数或结果的结构不一致返回解码错误；不会以错误的函数类型调用。

## 影响与验收

| 项 | 内容 |
|---|---|
| ABI | 布局不变；`flags` 位 1 与 `reserved` 获得含义，ABI 次版本升至 1.2 |
| 兼容 | 新使用方调用旧提供方：按名称调用，结果正确，单次调用多一次 CBOR 编解码。旧使用方调用新提供方：行为与此前相同 |
| 性能 | 双方均为新 SDK 且接口一致时，类型化调用增加一次 `u32` 比较。提供方在末尾追加方法、升级次版本后，仍使用旧次版本声明的使用方摘要不同，改走按名称调用，结果正确，单次调用多一次 CBOR 编解码；使用方用新版本接口重新编译后恢复类型化调用 |
| 实测 | 回归测试 `layout_digest::mismatched_layout_uses_named_invocation`：恢复修复前的检查后，方法顺序相反的调用使测试进程以 SIGSEGV 退出；修复后四种不一致均返回正确结果 |
| 版本 | cordis-abi 0.1.2，cordis-sdk 0.2.2（与 ADR-0055 同批） |

验收：

1. 宏单元测试：同一声明得到相同摘要；方法重排、原始类型改变、同步改异步各自改变摘要。
2. SDK 回环测试：使用方声明与提供方对象摘要一致时走类型化槽位；把提供方对象的摘要改为不同值后，同一调用经通用入口返回正确结果。
3. 由旧 SDK 构造、不带摘要的对象经通用入口调用成功。
4. `docs/abi/v1-layout.txt` 的布局比较、Miri、全量测试与 unsafe 审计通过。
