# ADR-0022 通用调用后的 ABI 模块上限

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | DOC-13 §1.1；M9 的 V-1–V-4 |

## 问题

DOC-15 要求每个原生服务同时支持类型化方法表和通用调用。通用调用还需在 CBOR 中传递服务编号，并在取消、解码失败和结果释放时归还对应对象引用。这些能力增加了方法名元数据、通用分派、拥有型结果缓冲和 Host 资源桥。M9 格式化后的 ABI src 为 2583 行，其中 230 行为 feature 门控的回环测试桥，产品源码 2353 行，原总上限为 2500 行。

## 选项

| 方案 | 职责与影响 |
|---|---|
| 保持单一 ABI crate，调整源码上限 | 缓冲、对象、Future、资源编号共享同一边界契约和安全包装 |
| 把通用调用拆到另一个 crate | 增加安全边界间的内部接口，源侧释放与编号所有权跨模块维护 |

## 决定

保持单一 ABI crate，将目标设为 2500 行，上限设为 3000 行。测试桥继续计入 src 总行数。通用调用的编码、资源引用及结果缓冲在 generic、buffer、host 等现有职责模块中实现，源码安全审计和 Miri 验收保持完整。

## 后果

M9 的实际总行数与产品行数分别记入 PROGRESS；后续超过 3000 行时按架构变更流程处理。内核和其余 crate 的上限保持既定值。
