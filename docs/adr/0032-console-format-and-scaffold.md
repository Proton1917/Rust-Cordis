# ADR-0032 终端日志格式与 Rust 脚手架

| 项 | 内容 |
|---|---|
| 状态 | 已采用，随 M12 复核 |
| 依据 | UPSTREAM-EXT `packages/create/src`、`packages/logger-console/src`；DOC-15 §3.1、§12.1 |
| 影响 | `cordis-dev`、`console-log`；DOC-11 §10、DOC-13 §7 |

## 问题

Rust 插件项目需要可以直接编译的本地模板，终端日志需要等级、实例标签、时间与多行布局。上游脚手架从 npm 取得 JavaScript 模板并交互选择安装步骤，终端导出器则使用 JavaScript 消息格式器与日历时间模板。Rust 项目的构建工具和 UP/1 标准输出通道具有不同的约束。

## 选项与判据

脚手架可以使用远端模板包，或随开发工具交付与当前 SDK 匹配的源码模板。采用随工具交付的模板可以使生成结果与接口修订保持一致，构建过程由 Cargo 解析固定修订的 SDK 依赖。

终端时间可以由手写日历换算或成熟日期库格式化。采用 `chrono = 0.4.42`，由其解析时间格式和处理本地时区；该依赖归属 `console-log` 插件。此版本的最低 Rust 版本满足插件 Rust 1.85 的要求。

## 决定

- `cordis new` 接受显式目标目录，支持新目录及已有空目录；非空目录返回错误并保留原内容。项目生成后给出 Cargo 编译和核心运行命令，调用者决定执行时点。
- `new-plugin` 的名称使用 Cargo 与原生宿主共同接受的形式：小写字母开头，后续使用小写字母、数字和短横线。命名检查在创建插件文件和追加部署条目前完成。
- 生成项目的构建命令固定为 `cargo build --target-dir target`，与 `runtime.plugin_dir = "target/debug"` 及 watch 路径对应。显式构建参数覆盖外部 `CARGO_TARGET_DIR`，产物和运行数据继续归属项目。存在该环境变量且插件引用缺席时，核心诊断同时指出构建目录及脚手架命令。测试中的工具构建和插件构建分别给出明确的输出目录。
- 模板随 `cordis-dev` 交付，构建脚本读取所在 Git HEAD 的既有提交编号并固定生成项目的 SDK 来源；源码归档构建可通过 `CORDIS_SOURCE_REVISION` 给定该编号，开发仓库可显式选择本机 SDK 路径。`new-plugin` 追加插件与实例配置，保留现有配置文本。
- `console-log` 采用上游的单字母等级前缀、实例标签、标签宽度与对齐、多行缩进、逐实例等级过滤、单行长度限制和可选时间差。默认日期显示为本地 `YYYY-MM-DD HH:mm:ss`；配置 `show_time` 使用 chrono 的 strftime 格式，空字符串关闭时间显示。
- 日志载荷已经是格式化后的 Rust 消息字符串，终端插件负责显示布局。由于 UP/1 使用宿主标准输出传输协议帧，终端日志写入标准错误。日期和时间差以终端插件接收事件的时刻计算，反映跨进程异步通知的到达时间。
- 配置字段采用 TOML 的下划线命名。保留 `level` 作为默认等级，`levels` 的实例名条目优先，其次为 `levels.default`。颜色能力默认由标准错误的终端属性决定，也可以显式配置。

## 后果

脚手架和终端插件与 Rust 工具链及独立宿主的职责一致。chrono 的时区和格式处理位于插件进程中；核心继续通过既有日志事件提供数据。
