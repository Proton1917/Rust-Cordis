# ADR-0027 进程组信号与子进程回收的统一所有权

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | DOC-13 依赖白名单；DOC-15 CP-7、CP-10；M10 process 模块 |

## 问题

真实重启测试在五次进程自然退出后记录了 EPERM。连接关闭监听与 Child.wait 分别处理终止和回收，组信号可能发生在直接子进程已经被回收之后。回收后的 PID 可重新分配，组清理需要在这之前结束，同时覆盖仍在该组内的后代进程。

## 选项

| 方案 | 行为 |
|---|---|
| 根据已保存的退出标志决定组信号 | 标志更新和内核回收之间仍有窗口 |
| 使用平台事件分别观察退出 | macOS 可用 kqueue，Linux 可用 waitid，需要维护平台分支 |
| 使用成熟库的安全 waitid 接口观察状态，再统一清理与回收 | 一个生命周期任务持有 Child，按明确顺序处理全过程 |

## 决定

采用 rustix 1.1.5 的 process 特性，通过安全的 waitid 接口使用 EXITED、NOWAIT、NOHANG 观察直接子进程。SIGCHLD 提供唤醒，状态读取始终针对该 Child 的 PID。

单一生命周期任务负责：观察退出或终止请求，在 Child 保持待回收状态期间用 nix 发送进程组信号，随后由 Child.wait 完成唯一回收。stop 和拥有者 Drop 向该任务提交控制信号。有效进程组的权限错误继续报告。

rustix 加入 cordis-supervisor 的产品依赖白名单，Tokio 启用 signal 特性。项目核心源码继续使用安全 Rust。

## 后果

组信号结束后才释放 PID 的系统所有权。正常退出、SIGKILL 与包含后代的组清理通过实际进程验证，结果记录在 PROGRESS。
