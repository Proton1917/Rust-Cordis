# ADR-0053：原生库副本的文件租约

| 项 | 值 |
|---|---|
| 状态 | 已批准（2026-11-15，设计方会话不可用，由用户委托复核后批准） |
| 日期 | 2026-11-15 |
| 依据 | DOC-11 SW-1/SW-9、CP-6、ADR-0012、第一性原理第 2、3、5 条 |

## 问题与职责

宿主为每次描述和装载创建独立副本，现有卸载流程只回收代码句柄。目录中的副本及验证印记随启动和替换持续积累。

文件存在的理由有两种：宿主持有该映像的代码租约；监管器的重启计划引用该副本。`restart_specification` 从宿主的 `LibraryInfo.path` 构建后续启动参数；宿主崩溃到重启之间，监管器仍持有这一计划。因此，回收条件由宿主的映像租约和监管器的重启引用共同决定。仅依据映射进程或宿主退出清理，会删除等待重启的来源。

## 文件租约与回收

共享文件租约使用标准库文件锁。副本所有者、正在复制该副本的宿主和持有重启计划的监管器分别取得共享租约。回收方在目录序号锁内取得副本的排他租约后，删除副本及其验证印记。进程崩溃由操作系统释放文件锁，下一次缓存操作回收已经失去全部引用的副本。

宿主在代码租约归零后归还副本租约；`Never` 保持映像装载策略，磁盘路径的引用单独管理。描述操作结束后立即归还本次副本。输入来自缓存时，在扫描旧副本之前保护全部启动输入，覆盖多库重启和新旧宿主交接。

序号保存在独立、原子发布的计数文件中，目录锁文件保持原 inode。首次使用时从现有库名接续最大序号；回收副本后序号继续递增。旧版本生成的文件缺少租约标记，按运维文档在服务完全停止并确认目录空闲后清理。

## 提议的代码范围

- `cordis-host`：副本预留、发布和失败回收接入文件租约；代码退役与描述结束归还文件租约。
- `cordis-process`：提供安全 Rust 的进程间文件租约和缓存目录操作，供宿主与监管器复用。
- `cordis-supervisor`：重启计划持有其来源文件的租约，候选计划、提交、回滚和 CP-6 恢复沿现有事务所有权转交。先合并 native/batch/lifecycle 中重复的计划与事务步骤，腾出新增代码所需行数，保持 6000 行上限。
- 内核、ABI 和 UP/1 的方法与布局沿用现有契约。文件租约协议在本 ADR 中固定，插件业务状态和缓存清理分别管理。

## 验证

使用真实宿主覆盖连续描述、反复启动和换库后的副本数量、共享目录中的并行装载、来源文件删除后的已装载服务、带验证印记的映像阈值重启，以及宿主崩溃后从原计划恢复。验证活动文件及重启引用在回收扫描期间仍可用，失去全部引用的副本可以释放。

批准要求先提交行为保持的重构并通过完整测试，再提交文件租约功能，各提交独立构建和验证。新增场景包括扫描与原生换库或批量替换并发、缓存来源对应的检查点恢复、SIGKILL 释放宿主共享租约后仍保留监管器持有的重启来源。主设计方会话恢复后可补充复核。

运维文档区分部署输入、验证凭据、业务状态和可重建的宿主副本；历史目录手动清理前停止相应核心与全部宿主，并用打开文件查询确认目录空闲。
