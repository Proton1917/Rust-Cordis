# ADR-0019 两种插口、分组与跨进程通用调用

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | `DOC-12` §7、§10（`V-1`、`V-3`、`V-4`）；`DOC-13` §3.3（`V-2`）；`DOC-11` §6、§10；`DOC-15` §4、§6、§8 |

## 问题

`ADR-0018` 把全部插件移出核心进程。项目所有者要求两种插口：Rust 原生插件速度优先；任何语言的插件都能插入，首先 Python 与 TypeScript。两种插口上的插件需要互相调用、共用同一套接口与生命周期。

## 选项

### 原生插件如何在核心外运行

| 选项 | 内容 | 代价 |
|---|---|---|
| A1 | 每个原生插件一个宿主进程 | 原生插件之间的所有调用都跨进程 |
| A2 | 按部署时指定的分组，一组一个宿主进程，组内直接调用 | 同组插件共担崩溃 |

### 跨进程如何调用服务

| 选项 | 内容 | 代价 |
|---|---|---|
| B1 | 为每种语言、每个接口生成专用的跨进程桩代码，核心不参与 | 核心无法路由、监视与回收 |
| B2 | 每个服务对象都支持按方法名的通用调用，参数与结果为 CBOR；核心按对象编号路由 | 跨进程调用需要编解码 |

## 判据

1. 同组原生插件之间的调用速度与第二阶段相同。
2. 任意两种插口上的插件可以互相调用，核心能路由、记录、在进程崩溃时回收。
3. 插件不需要为改变分组而重新编译。

## 决定

选 A2 与 B2。

- 高速插口：原生插件经 ABI v1 由 `cordis-host` 装载；`cordis.toml` 的 `group` 决定分组，默认每个插件库自成一组。
- 通用插口：任何语言的进程插件，经 `UP/1` 与核心通信。
- 核心只认 `UP/1`。`cordis-host` 对核心而言是一个代表组内全部原生插件的进程插件。
- ABI v1 的 `ObjectHeader` 增加类型化方法表标志、方法名表与 `invoke`/`invoke_async`（`V-1`）；参数为 CBOR 数组，结果为单个 CBOR 值（`V-3`）；描述符 `format` 区分原生库、进程插件与保留的 WebAssembly（`V-4`）；`#[interface]` 同时生成两种入口，调用方代理在类型化方法表缺失时走通用调用（`V-2`）。
- 跨进程的事件监听器一律以通知方式调用；需要返回值的派发只用于核心内部监听器。

## 后果

- `M8` 已冻结的 ABI v1 在 `M9` 中解除冻结，`M11` 重新冻结。
- 部署者以分组在速度与故障隔离之间取舍：调用频繁且彼此可信的插件同组，新写或依赖 C 库的插件单独成组。
