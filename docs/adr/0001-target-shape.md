# ADR-0001 目标形态：论文范式的 Rust 原生内核

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-11，项目所有者确认） |
| 影响 | `DOC-00` `G1`–`G3`、`P1`；`DOC-02` 全文 |

## 问题

“用 Rust 重写 cordis 内核”有三种可能的交付形态，它们的接口设计互不兼容。

## 选项

| 选项 | 内容 | 代价 |
|---|---|---|
| A | Rust 原生内核：实现 `PAPER` 的模型，接口按 Rust 习惯设计，供 Rust 程序以组件形式在其上构建 | 接口与 `UPSTREAM` 不逐字相同，上游用例需要移植 |
| B | 以 napi 或 wasm 嵌回 JavaScript，替换 `UPSTREAM` 的 `packages/core` 并直接运行上游 vitest | 代理层必须留在 JS 一侧，每次属性访问跨越语言边界；交付物服务于 JS 生态 |
| C | 先 A 后 B，两者都列为正式里程碑 | 范围最大 |

## 判据

1. 项目所有者的意图：内核是今后各项目的核心，今后的程序按 `PAPER` 的范式以组件形式编写，需要一个 Rust 上的内核。
2. `PAPER` §5.3：上下文范式与语言无关，只由两个可组合性维度定义。

## 决定

选 A。`PAPER` 是规范，`UPSTREAM` 是参考实现（`DOC-00` §1）。

## 后果

- 接口以 `DOC-02` §7 的映射表为准，每一行保持 `UPSTREAM` 的语义。
- 行为一致性通过移植上游的 177 条用例验收（`DOC-04`）。
- 内核不依赖具体执行器（`DOC-00` `P9`）。这使选项 B 的绑定层将来可以加在同一内核之上，本次不做。
