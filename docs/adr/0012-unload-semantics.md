# ADR-0012 卸载语义：保证代码静止，默认不关闭库

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-11） |
| 影响 | `DOC-10` `G9`、`Q4`、`R7`、`R11`；`DOC-11` §6 `SW-9`；`DOC-12` §11 |

## 问题

插件库被替换后，旧库的代码与数据需要退出使用。需要决定装载器承诺什么，以及何时关闭旧库（`dlclose`）。

## 事实

1. 内核的效应回退保证旧实例登记的监听器、服务、清理函数都已撤销（第一阶段 `T-EFF-*`、`T-LIF-*`）。
2. 效应之外仍可能存在指向旧库的引用：其他插件持有的服务对象副本、未按 `PR-1`、`PR-2` 绑定到效应的任务与线程。
3. 关闭一个仍有代码在运行的库，后续执行是未定义行为。
4. 使用了线程局部变量的动态库，在 macOS 上关闭后通常不会从内存移除；在 Linux glibc 上，注册了线程局部析构函数的库在相关线程退出前也不会被移除。Rust 标准库使用线程局部变量，因此大多数 Rust 插件库在两个平台上都难以真正移除。

## 选项

| 选项 | 内容 | 代价 |
|---|---|---|
| A | 替换后立即关闭旧库 | 事实 2 中的引用会导致未定义行为 |
| B | 租约归零后关闭旧库 | 依赖租约覆盖全部引用；按事实 4，关闭后映像通常仍在内存中，收益有限 |
| C | 保证代码静止（租约归零），默认不关闭旧库；`B` 作为可选策略 | 每次替换累积一份旧库映像 |

## 判据

1. 内存安全排第一（`DOC-10` §8）。
2. 承诺的内容必须能在两个目标平台上验证。

## 决定

选 C。

- 装载器承诺：替换完成后，旧库的租约在有限时间内归零，归零后旧库的代码不再被调用。替换报告记录归零耗时。
- 配置 `unload = "never"`（默认）：不关闭旧库。
- 配置 `unload = "when-unleased"`：租约归零后关闭旧库。是否移除映像由平台决定，装载器不作承诺。
- 新版本的库一律复制到唯一路径后打开（`SW-1`），保证新代码生效与旧库是否关闭无关。
- 副本路径采用 `.cordis/lib/<插件名>-<单调递增序号>.<扩展名>`。验证门保存 `.cordis/verified/` 中的已验证副本，候选通过完整字节比对关联到验证记录；被拒副本同样按完整字节比较识别重复投递。

## 后果

- 频繁替换会累积旧库映像，`RM-6` 实测每次替换的增量，运行时在 `status.json` 报告累积的旧库数量。需要回收时做一次有状态重启（`DOC-11` §9）。
- 租约在超时后仍未归零时，运行时记录持有租约的对象类别（接口名、回调、任务），作为插件违反资源规则的诊断。
