# ADR-0054：已确认程序绑定的离线查询

| 项 | 值 |
|---|---|
| 状态 | 已批准（用户授权 Claude 代为批准，消息 ebd936bd-ad3d-44d3-9935-572fa1e216d1） |
| 日期 | 2026-11-16 |
| 依据 | DOC-11 §10、DOC-15 §3.1、ADR-0031、第一性原理第 2、3、5 条与带版本契约要求 |

## 问题与职责

部署工具在核心停止后，需要按实例取得最后持久确认的程序引用及安装目录，确定停机升级期间保留的版本。现有 `cordis status` 读取运行快照；有序退出后的快照实例列表为空。运行时在 `control/sources.rs` 维护的程序绑定包含这些事实，目前外部工具需要直接读取内部持久格式。

实例的来源选择、替换确认与重启恢复由运行时掌握。查询职责放在 `cordis-runtime` 的命令行入口，来源解码由现有绑定模块提供。内核、supervisor、routing、channels、ABI、UP/1 和插件服务接口沿用现有契约。程序回收策略继续由部署工具根据自己的升级与回滚要求决定。

## 命令与版本

新增以下入口：

```sh
cordis status --offline --config /srv/example/cordis.toml
```

`--config` 保留 `-c` 和默认值 `cordis.toml`。普通 `cordis status` 沿用运行快照输出。离线模式输出一个 UTF-8 JSON 对象，退出码 0 表示整份结果读取成功；参数错误沿用 Clap 行为，配置或记录读取、解析失败时退出码为 1，诊断写入标准错误，标准输出保持为空。

公开 JSON 契约的首版为 `schema_version: 1`，与程序发行版本及 `cordis.runtime` 服务版本分别管理。同一主版本允许追加字段，消费者忽略未知字段；已有字段的名称、类型和语义保持稳定，删除字段或改变字段类型、含义时提升 `schema_version`，并在发布说明中记载。消费者检查版本后再使用实例映射。

示例：

```json
{
  "schema_version": 1,
  "instances": {
    "store": {
      "declared_source": "store",
      "installed_reference": "installed-7",
      "plugin_directory": "/srv/example/plugins"
    }
  }
}
```

| 字段 | 类型与语义 |
|---|---|
| `schema_version` | 整数，首版固定为 1 |
| `instances` | 以部署实例名为键的对象，包含持久记录中的全部实例；序列化按实例名排序 |
| `declared_source` | 字符串，该绑定确认时记录的基础程序声明；管理创建的实例沿用运行时记录的声明规则 |
| `installed_reference` | 字符串，该实例最后持久确认的程序引用；消费者按不透明引用处理 |
| `plugin_directory` | 字符串，该绑定对应的插件安装根目录，输出为绝对路径 |

`plugin_directory` 是解析程序引用所用的安装根目录。原生插件引用可以指向单文件，进程与网页插件引用可以指向目录。基础源码位置由 `declared_source` 表达。

## 读取与一致性

配置文件沿现有 `deployment::load` 规则定位状态目录，包含普通部署、自定义 `state_dir` 和应用包的状态位置。相对的已记录插件目录以配置文件真实所在目录为基准展开，绝对记录直接保留。停机后编辑 `plugin_dir` 或实例声明时，查询继续使用持久记录中的值；变更由后续运行入口采用。路径展开使用词法连接，磁盘中对应程序被移动或删除后仍能查询原记录。

读取侧复用程序绑定的类型和受限文件读取入口，显式构造公开输出。内部文件的路径与序列化布局继续由运行时维护，外部工具依赖命令和公开 JSON 字段。

一次读取取得原子发布记录的完整旧版或新版。查询在核心运行期间也可执行，此时返回读取时最近一次成功持久化的确认结果。候选确认期沿用事务前的记录，确认成功并持久化后出现新引用，失败回滚后继续呈现原引用。

记录覆盖曾经成功确认且仍保留的部署实例。停用或依赖等待的实例保留既有确认记录；首次激活前的实例缺少相应条目。运行时提交移除后按现有规则清除绑定。核心进程异常结束时，以最后一次成功发布的记录为准。

读取只访问配置和已发布的绑定文件。查询完成后释放文件句柄；插件发现、插件装载、状态目录创建及持久写入均属于运行入口的职责。绑定文件缺席、损坏、超出读取上限或无法访问时返回错误；有效的空映射输出 `instances: {}`。

部署工具将这些引用加入升级保留集合。回滚版本、分发包自身的来源和其他部署共享的版本由部署工具按相应事实继续保留；本查询提供当前逐实例确认绑定。

## 实现范围

- `cordis-runtime/src/cli.rs` 与 `main.rs`：增加离线选项及分派，共用配置与状态目录定位。
- `cordis-runtime/src/control/sources.rs` 与 `control.rs`：由绑定所有者提供受限读取及公开结果转换，运行时恢复与查询复用内部解码定义。
- `cordis-runtime/tests/runtime.rs` 及其相关测试模块：扩展真实部署、独立分组替换、确认回滚与停止后的命令行查询覆盖。
- DOC-11、DOC-15、README 和插件技能的部署文档：说明命令、JSON 契约、目录含义与持久确认时点，并引用本 ADR。

## 验收

复用真实运行时夹具及 TestGuard，预期结果取自实际管理安装返回值、基础声明和测试部署目录。先在既有版本执行一次目标离线命令，保存缺少选项的失败证据；实现后复用相同触发方式确认输出。

1. 同一基础来源的两个独立分组使用不同已安装版本；有序停止后逐实例查询分别返回各自确认引用、原声明和安装根目录，普通状态查询继续输出已停止快照。
2. 停机后修改基础声明和 `plugin_dir`，查询仍返回最后确认的绑定；从其他工作目录使用显式配置路径查询，目录解释保持一致，来源程序存在与否独立于查询结果。
3. 在既有真实确认期回滚场景中，离线命令在候选确认期间及回滚后均返回原引用；成功替换后返回新引用。已确认实例的停用保留和提交移除沿已有持久规则验证。
4. 查询已存在的真实状态时，配置、绑定及其他状态文件的内容与修改时间保持；记录缺席、截断、必需字段缺失及字段类型错误各返回失败及标准错误，成功输出完整 JSON。真实移除全部实例后，查询返回有效空映射。
5. 读取线程先确认旧版并通知提交线程，在十秒截止时间内观察新版，每次结果均为旧版或新版完整记录；提交结束后的查询继续返回新版。停机后的引用与停机前运行快照中的程序引用一致。查询沿普通文件读取执行，核心事务锁由运行入口持有。
