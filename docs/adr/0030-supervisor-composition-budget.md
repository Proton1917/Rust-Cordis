# ADR-0030 组合接口与原生换库的监管器代码上限

| 项 | 内容 |
|---|---|
| 状态 | 已实施，交设计方复核（2026-11-12） |
| 影响 | DOC-13 §1.1；ADR-0026；M11 的 ADR-0025 组合接口、原生换库及回滚持久化 |

## 问题

M11 将派生上下文、Scoped 服务缓存、子组件、原生单库替换与映像阈值重启接入唯一核心。手动回滚还要保留替换前的原快照，SW-9 清理失败需要把本次事务的提交事实交给运行时持久化部署。按 cloc 2.10 的 Rust 注释规则统计，监管器为 4562 代码行 / 4912 总行，超过 ADR-0026 的 4500 代码行上限。

## 已完成的职责调整

进程启动、组信号与唯一回收已提取到 cordis-process，管理数据类型由 cordis-types 共享。监管器内部按生命周期、请求分派、加载纪元、资源路由、派生视图、原生库切换与元数据额度分模块；组件描述解析、状态导出、候选确认和恢复步骤采用共同实现。关键函数按步骤拆分并保留条款文档。

## 决定

cordis-supervisor 的目标设为 4500 代码行，上限设为 5500 代码行。代码行排除空行、普通注释与文档注释，计量方法继续采用 DOC-13 §1.1。其余 crate 沿各自上限。

## 后果

生命周期事务和资源所有权继续在同一监管器内协调，实际行数随里程碑保存。超过目标时说明具体功能来源，超过上限时按项目规则提交 ADR。设计方依据本次组合与恢复职责复核调整。
