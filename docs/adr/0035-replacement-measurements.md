# ADR-0035 替换事务的计时与影响实例统计

| 项 | 内容 |
|---|---|
| 状态 | 已实施，交设计方复核 |
| 影响 | DOC-10 RM-3、RM-4；DOC-15 §8.7；Runtime 1.3；M14 |

## 问题

一次原生库替换可能在退役映像达到阈值后继续执行整组有状态重启。RM-3 和 RM-4 需要覆盖这次管理操作涉及的实例与实际阶段，使组内无关实例因阈值重建产生的变化进入同一条记录。

## 决定

RM-4 的起点是串行事务执行者开始处理替换，位于候选准备之前；终点是本次替换及其阈值重启涉及的实例全部进入 Active。该区间覆盖文件复制、描述符握手、状态导出、生命周期切换和依赖重建。确认期等待由完整管理调用的 wall_ms 记录；阈值重启沿用原生替换的计时起点，并扣除前一确认期经过的时间。

GroupReplaceReport 追加带默认值的 pause_ms，Runtime 次版本升为 1.3。原生 SwapReport 的 pause_ms 使用最终稳定时刻；发生阈值重启时，affected_instances 根据原始纪元与最终纪元统计。客户端记录 RPC 完整调用耗时，验收另保存命令文件收发在内的外部耗时，以保留两个观测位置的实际范围。

原生提交按保存原快照、退役原库、执行阈值策略、发布最终报告拆分。冻结资源通过整体移出和析构释放；组内替换与整组重启继续使用相同的状态迁移实现。

## 代码预算

按 cloc 2.10 的 Rust 规则、`--skip-uniqueness` 和工作区内中间目录计量，监管器当前为 5500 代码行、5918 总行。分组报告的提交、完成、失败和回滚共用 `record_group_report`；局部 catalog 守卫明确持有锁。普通替换复用稳定阶段得到的影响数，阈值重启后再统计整次操作的变化。

DOC-13 的 4500 行目标与 5500 行上限继续沿用 ADR-0030。实现保持完整计时、资源释放和各阶段报告发布，达到上限。后续职责调整继续围绕生命周期和资源所有权进行。

## 后果

AC-9 固定执行 8 个实际线程下的 50 次替换，逐轮保存 RM-3、RM-4、完整管理调用时间及进程常驻内存。阈值重启对应的组 PID、无关实例纪元与状态继承同时进入验收记录。全部预定轮次结束后统一计算中位数、最大值和内存增量。
