# ADR-0044 配置调和的稳定状态

| 项 | 内容 |
|---|---|
| 状态 | M20 实施依据 |
| 影响 | DOC-11 §6、§10；DOC-15 AU-14；supervisor 批次事务、runtime 配置管理 |

## 问题

AU-14 的真实三语言场景中，移除 Rust 服务后，两页按内核依赖规则清理界面并进入 Pending。配置管理复用批次事务时，SW-7 的 Active 检查把这一有效状态判为失败，并恢复被移除的提供方。版本替换与配置调和具有不同的目标状态，需要在共享事务中明确表达。

## 决定

| 操作 | 稳定判据 |
|---|---|
| 普通插件版本替换、纯代码替换批次 | 沿 SW-7 确认受影响实例 Active |
| add、remove、configure、reload，以及带完整配置重读的批次 | 等待内核调和完成，接受 Active 与因依赖缺席进入的 Pending |

Manager 的 replace_batch 保持版本替换语义；新增 reconfigure_batch 共用来源准备、状态导出、应用、确认和恢复步骤。配置模式保留描述符、版本、配置解析与资源预算检查，依赖是否可用由内核决定。Failed、执行错误、清理错误及截止时间继续触发恢复。配置模式随事务原快照保留，恢复时按原部署的同类状态判据确认。

runtime 按操作携带的配置目标选择模式。批次中同时携带配置与代码变化时，最终部署可以包含等待依赖的组件；具有实际执行错误的候选仍进入回滚。用户通过状态接口读取每个实例的实际状态。

## 选项与判据

另一种方式是在运行时恢复单独的配置提交实现，并维护网页与后端的第二套恢复步骤。共享事务保留唯一的提交、原状态及持久化处理，稳定策略只决定允许的最终状态，因此采用前述方式。

此策略沿用内核 T-COE 的依赖语义；supervisor 复用内核已经计算的 Pending 状态。原有版本替换的公开调用路径和签名保持。

## 验证

修复前证据为 target/web-m20/frontend/evidence/dependencies-first/results/002.json。固定场景依次移除并插回 Rust、Python、TypeScript 提供方，要求两页 Pending、界面撤回、服务恢复后重新 Active，并完成实际跨语言调用。既有坏 apply 与事务回滚用例继续验证失败处理。
