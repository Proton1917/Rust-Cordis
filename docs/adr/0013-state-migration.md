# ADR-0013 状态迁移：导出器是效应，状态块自描述，转换由新实现负责

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-11） |
| 影响 | `DOC-11` §5、§6、§7、§9；`DOC-12` §9 函数 14、15 |

## 问题

`PAPER` 的组件模型在重载时回退全部效应，然后从头执行 `apply`，组件在内存中的数据不保留。热替换与核心升级需要保留部分数据。需要决定数据如何从旧实例交给新实例。

## 选项

| 选项 | 内容 | 代价 |
|---|---|---|
| A | 不提供迁移，组件自行把全部状态写入持久存储 | 每个组件自行实现，替换时机与写入时机无法协调 |
| B | 运行时在替换时调用组件登记的导出器，把状态块交给新实例 | 需要定义导出时机、写入冻结与版本规则 |
| C | 直接把旧实例的内存对象交给新实例 | 新旧实例来自不同的库，类型布局不保证一致，违反 `Q3` |

## 判据

1. 新实现可以由不了解旧实现的人或 AI 编写，只依据契约。
2. 迁移失败时可以回到替换前的状态。
3. 与 `PAPER` 的效应模型一致。

## 决定

选 B。

- 导出器通过 `ctx.export_state` 登记，是一个效应。实例停用时导出器随之撤销，运行时不会调用到已停用的实例。
- 状态块包含模式名、版本、CBOR 字节，按 `DOC-11` §5.4，新实现声明接受的版本范围，自行转换旧版本。旧实现不需要知道新版本。
- 导出时组件冻结写入（`DOC-11` §5.3），保证状态块与停用前的数据一致。
- 回滚使用替换开始时的状态块（`DOC-11` §5.5）。
- 核心有序退出与启动复用同一机制，状态块写入状态目录。

## 后果

- 状态模式是契约的一部分（`DOC-11` §2），契约套件应覆盖导出与继承的往返。
- 没有导出器的组件在替换后以空状态启动。
- 持久化数据（数据库文件等）不经过状态块，由插件写入自己的数据目录（`PR-7`）。
