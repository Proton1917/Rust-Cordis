# ADR-0021 进程组控制与输入模糊测试

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | DOC-13 依赖白名单；DOC-15 CP-7、CP-9；M10–M14 |

## 问题

核心需要在超时、协议错误和退出时结束插件进程组，并等待子进程退出。UP/1、配置、清单和状态读取还需接受每个目标持续 30 分钟的模糊测试。核心源码继续遵守 Q0 的安全 Rust 约束。

## 选项与判据

进程组创建使用标准库和 Tokio 的进程接口，信号发送使用提供安全 API 的成熟 POSIX 库。模糊测试复用 cargo-fuzz 与 libFuzzer，输入经过产品解析函数，保留崩溃输入和有限运行时长。

## 决定

- cordis-supervisor 采用 nix 0.31.3 的 process、signal 特性发送进程组信号；Tokio 负责管道、截止时间和子进程等待。系统调用的封装位于第三方依赖，项目核心源码使用安全接口。
- 模糊测试使用 cargo-fuzz 0.13.2，测试目标依赖 libfuzzer-sys 0.4.13。libfuzzer-sys 仅进入独立 fuzz 工作区；cargo-fuzz 安装在工作区的 target/tools，构建产物和 corpus 位于 target。
- 每个指定目标设置 max_total_time=1800，并限定单次输入大小、单次执行时间与内存。发现失败后修复对应产品解析路径，保存该输入作为回归证据；修复影响的目标重新执行规定验证。
- cordis-up 负责帧与 CBOR 输入约束，目标 1500 行、上限 2500 行；cordis-supervisor 负责进程与路由，目标 2000 行、上限 3500 行。宿主与运行时沿用 DOC-13 的既有上限。

## 后果

进程异常和核心退出通过同一进程组释放路径处理。模糊测试依赖与正式产品构建分离，执行结果及持续时间记入 PROGRESS。
