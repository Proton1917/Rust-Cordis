# ADR-0016 依赖可用性与组件定义退役

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | `DOC-11` §3.4；`DOC-12` §10 `DependencyV1.required`；`DOC-13` `K-2`、`K-4`；M10 装载适配与库关闭 |

## 问题

`DependencyV1.required` 允许组件声明可选接口。同一接口主版本的多个使用方还可以要求不同的最低次版本。内核现有声明均为必需项，提供方可用性谓词对全部使用方采用同一结果，需要把这两项声明条件纳入每个使用方的依赖解析。

## 选项

| 选项 | 方法 | 结果 |
|---|---|---|
| A | 每条内核依赖声明保存必需标志和可用性谓词 | 满足性、纪元、已提交绑定及依赖清理继续经过同一生命周期机制 |
| B | 装载器为不同版本门槛分别登记衍生服务 | 一个接口产生多个绑定，版本转换和清理关系需要额外维护 |

## 判据

1. 可选接口缺席时组件可以激活，接口出现与消失时组件重新加载。
2. 同一主版本的每个使用方按各自的最低次版本判断可用性。
3. 使用方持有实际提供绑定的依赖关系，提供方等待使用方清理。
4. 第一阶段的默认声明行为和类型化服务接口保持原义。

## 决定

采用 A。`K-2` 的依赖声明增加 `required: bool` 和可选的 `DependencyPredicate`，后者为 `Arc<dyn Fn(&AnyArc) -> bool + Send + Sync>`。已有声明入口采用 `required = true`、空谓词。命名入口 `Inject::with_named_options(name, required, predicate)` 供装载器传入这两项条件。

依赖解析在锁内取得提供绑定、值、声明谓词及既有提供方可用性谓词的快照，在锁外执行谓词，再按现有 `refresh` 的状态确认规则提交结果。声明谓词发生 panic 时记录使用方错误，本次将该项视为缺席。提交确认覆盖绑定身份、提供方状态，以及参与谓词计算的值和声明谓词的共享身份。

必需项缺席使目标纪元为 `Inactive`。可选项缺席仍允许目标纪元为 `Active`，该项的纪元槽为 `0`；真实绑定的编号从 `1` 开始。可选项出现、消失或绑定身份变化时，纪元随之变化，使用方经过完整清理后重新加载。`committed` 保存实际存在的绑定，并把使用方登记到这些绑定的依赖方集合。可选项存在期间的清理顺序与必需项相同。

命名读取继续遵循当前加载的 `committed` 视图。可选项在该视图中缺席时，读取返回明确的缺席错误，由调用方通过 `Result` 处理。命名提供的值保持原始 `AnyArc`。

装载器将接口实现包装为由宿主持有的对象，保存已解析的主版本、次版本及 ABI 对象租约。声明谓词检查这个包装中的次版本是否达到使用方要求。版本条件属于每条声明，接口仍以 `<名称>@<主版本>` 登记一个真实服务绑定。次版本不足使必需使用方保持 `Pending`，可选使用方把该项视为缺席；装载器记录具体版本差异。

组件定义的显式退役通过 `Registry::forget(&ComponentDef) -> Result<()>` 完成。它沿别名链定位终点；终点运行时仍有实例时返回错误。实例全部释放后，移除解析到该终点的别名和终点定义，定义闭包在内核锁外释放。装载器关闭库、移除无实例组件时显式调用该入口。默认的 `replace` 与旧别名重新挂载继续保留当前终点定义，沿用第一阶段行为。

## 后果

M10 的内核补充及真实插件用例覆盖必需和可选依赖、不同最低次版本、提供方替换、消费者清理顺序，以及旧库租约释放。第一阶段声明采用默认参数，其满足性和纪元含义保持原值。
