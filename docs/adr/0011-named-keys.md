# ADR-0011 跨边界的服务与事件以名称识别；名称由宿主拥有

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-11）。补充 `ADR-0004` |
| 影响 | `DOC-13` §2 `K-1`–`K-3`；`DOC-12` §9 函数 9–13 |

## 问题

`ADR-0004` 以键类型的 `TypeId` 识别服务，事件同样以类型识别（`ADR-0006`）。单独编译的插件中，同一源码类型的 `TypeId` 不保证相同，插件的类型也不进入内核（`Q3`）。另外，内核以 `&'static str` 保存组件名、服务名，插件提供的名字位于插件库内存中，旧库静止后这些引用不能继续存在。

## 选项

| 选项 | 内容 | 代价 |
|---|---|---|
| A | 宿主侧为每个接口生成一个 Rust 键类型 | 接口在运行时才出现，宿主无法为它定义类型 |
| B | 内核增加以名称为键的入口，值为 `Arc<dyn Any + Send + Sync>`；类型化键以 `K::NAME` 映射到同一命名空间 | 内核增加一组入口，约数百行 |
| C | 装载器在内核外自建服务表 | 绕过内核的余效应，依赖方无法随提供方变化自动重建，失去 `PAPER` 的核心保证 |

## 判据

1. 插件之间的依赖必须享有内核的余效应语义：提供方出现时加载、替换时重载、消失时卸载，依赖方先于提供方清理。
2. 第一阶段的类型化接口与全部用例保持不变。
3. 内核中不残留指向插件库内存的引用。

## 决定

选 B，并把内核中的名称改为宿主拥有的字符串。

- 命名空间：类型化键的 `K::NAME` 与命名键共用一个名称表。同一名称同时被类型化键和命名键使用时，以第一次登记的方式为准，另一方式登记返回错误（沿用 `ADR-0004` 的冲突处理）。
- 依赖匹配、读取、隔离和通知以名称关联；提供方登记方式决定值的类型约束。`Inject::with_named` 可声明类型化提供方的名称，类型化读取在转换边界检验值表示。命名元数据按后层覆盖，类型化元数据沿用各自的 `Merge`。
- 接口标识 `kv@1.2` 在内核中的键名为 `kv@1`（名称加主版本）。次版本匹配由装载器在注入前检查（`DOC-11` §3.4），内核只看主版本。
- 事件同理，键名为 `<事件名>@<主版本>`。
- 第一阶段的类型化事件继续按 `TypeId` 区分，保留同名类型和派发族的已有行为。命名事件按名称与派发族识别，名称登记表负责类型化/命名方式冲突。

## 后果

- `K-1`：`ComponentDef.name`、名称表、日志名称改为 `Arc<str>`。公开接口中接收 `&'static str` 的位置改为接收 `impl Into<Arc<str>>`，原有调用不需要修改。
- 命名键的值是 `Arc<dyn Any + Send + Sync>`，装载器在其中存放持有租约的 `AbiObject` 包装。
