# ADR-0058：原生退役资源计量与恢复依据

## 决策

宿主分别报告累计退役数 `retired_total`、归还库句柄数 `closed_total`、仍拥有的退役句柄 `open_retired_handles`、实际退役租约 `retired_leases`、退役文件租约 `retired_cache_pins` 和可选的物理映像观察 `mapped_retired_images`。旧字段 `retired_images` 继续表示累计退役数。

Linux 的物理观察读取 `/proc/self/maps`，以缓存副本的设备号与 inode 匹配，覆盖文件改名和已删除但仍映射的文件。同一文件身份计为一个映像。库句柄归还后，一次观察确认相应 inode 已经离开映射集合，或该 inode 已经复用于新的活动副本时，释放紧凑历史记录。平台缺少观测能力、读取失败或文件身份不完整时，该指标为空。句柄关闭与映像解除映射分别记录。

`library_status` 执行物理观察；`library_retire` 返回轻量所有权计数。累计策略和句柄策略复用退役应答，映像策略在清理完成后读取一次物理观察。宿主每归还 256 个库句柄，额外观察一次映射并回收已解除映射的紧凑记录，因此直接调用退役接口而长期不查询状态的宿主也会摊销清理。观测可用时，清理间隔最多留下 256 条尚未确认解除映射的关闭记录；仍映射的记录继续代表实际资源。观测失败时保留记录，后续周期继续尝试。身份集合不完整时，完整映射指标继续返回空值；成功观测仍会清理其中已知身份的关闭历史。

宿主最多保留最近 256 条已关闭库的完整诊断记录，仍拥有句柄的退役库继续保留完整记录；累计计数及紧凑物理记录拥有独立寿命。

## 配置与兼容

`[runtime].retired_image_basis` 接受：

- `cumulative`：默认值，累计退役数超过 `retired_image_limit` 时恢复整组；默认阈值 20 保持第 21 次退役恢复。
- `open-handles`：采用宿主实际仍拥有的退役库句柄数。
- `mapped-images`：采用操作系统观测到的退役映像数。

新的计量字段为可选协议扩展。旧宿主或物理指标不可用时，监管器采用累计数。原生库的 `unload` 策略继续独立控制归零后的句柄释放；所有同步执行、异步任务和析构租约继续由原有租约规则约束。

## 验证

定向场景在 `when-unleased` 下执行三次真实换库，使用 `open-handles` 和零阈值，核对累计数、句柄归还、活跃退役租约、宿主连接身份及业务状态 137。`Never` 场景分别使用句柄和映像策略：第一个退役句柄仍保留，第二个超过阈值 1 后恢复整组并保留状态 137。Linux 单元场景以正在执行的二进制校核设备号与 inode 的实际映射，并覆盖历史身份去重、inode 复用和解除映射后的清理。周期清理场景直接回放 768 次关闭记录转换，不查询库状态：仅触发 3 次实际 `/proc/self/maps` 读取，保留真实映射身份并释放已解除映射的历史记录。原累计阈值场景保留第 21 次换库恢复和拒绝候选恢复的接受条件。
