# ADR-0018 核心隔离：核心进程不运行插件代码

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | `DOC-10` 新增 `Q0`、删除 `Q8`、修订 `G12` 与 `R7`；`DOC-13` crate 划分与 `B-2`；`ADR-0009`；`ADR-0017`；`DOC-15` §2、§3、§5 |

## 问题

`ADR-0009` 把原生插件库装进核心进程，`DOC-10` 以 `Q8`“原生插件是可信代码”接受其风险：插件中的段错误、栈溢出、`abort`、`std::process::exit`、内存破坏会终止或损坏核心进程。操作系统以进程为单位处理这些故障，同一进程内无法隔离。项目所有者要求核心是系统中最稳定、长期不动的部分，任何插件都不能影响它。

## 选项

| 选项 | 内容 | 代价 |
|---|---|---|
| A | 维持现状，原生插件在核心进程内 | 不满足项目所有者的要求 |
| B | 原生插件默认进程内，可选隔离运行 | 默认部署仍然把核心的稳定性交给插件 |
| C | 所有插件都在核心之外的进程运行；原生插件由插件宿主进程按分组装载，同组之间直接调用 | 跨分组调用多一次进程间往返；需要实现进程监管与 `UP/1` 协议 |

## 判据

1. 任何插件的任何故障都不使核心进程终止、卡住或损坏（项目所有者的要求，排第一）。
2. Rust 插件之间在需要时仍能直接调用。
3. 核心可以被完整审计：不含 `unsafe`，不含插件代码。

## 决定

选 C。新增首要公理 `Q0`：核心进程只运行核心自己的代码，所有插件都在核心之外的进程中运行，核心与插件之间只交换消息。

推论：

1. 核心进程不调用 `dlopen`，不依赖 `cordis-abi` 与 `cordis-sdk`，不执行插件提供的函数指针。
2. 核心的全部 crate 不使用 `unsafe`。
3. 核心把插件进程发来的一切数据当作不可信输入，执行 `DOC-15` 的 `CP-1`–`CP-11`。
4. 插件进程崩溃时，核心回收其全部效应与服务并按策略重启它。
5. 核心自身崩溃由操作系统的服务管理器拉起，状态从定期检查点恢复（`DOC-15` §5.1）。

## 后果

- `Q8` 删除。`R7`（调用已失效库的代码）只存在于插件宿主进程内。
- 跨分组、跨语言的调用有进程间往返开销，由 `RM-7` 实测；同组原生插件之间的调用速度不变（`RM-9`）。
- 第二阶段 `M10` 起的里程碑按 `DOC-15` §15 重排。
