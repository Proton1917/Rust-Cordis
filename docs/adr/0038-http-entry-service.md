# ADR-0038 HTTP 静态资源与页面入口服务前移至 M16

| 项 | 内容 |
|---|---|
| 状态 | 已实施，交设计方复核 |
| 影响 | DOC-15 §11.3、§11.6、§15；DOC-13 依赖与插件布局；M16、M20 |

## 问题

M16 的窗口插件通过 cordis.web@1 取得页面地址和启动令牌。该接口由 HTTP 插件提供，原里程碑把 HTTP 插件与网页宿主一起安排在 M20。窗口的实际页面加载与发布包验收需要可运行的 HTTP 服务。

## 决定

M16 交付生产 HTTP 原生插件、web-api 接口 crate、静态资源服务、默认启动页及每次激活生成的随机会话令牌。HTTP 插件默认独占宿主分组并绑定 127.0.0.1，默认端口 0 由操作系统分配。

`cordis.web@1.0` 定义一个同步查询方法：

```rust
fn entry(&self) -> Result<WebEntry>;

struct WebEntry {
    url: String,
    token: String,
}
```

入口 URL 的片段为 `cordis_token=<令牌>`，窗口直接加载该地址。页面可通过标准 URL API 读取片段，`/_cordis/session.js` 同时提供本次激活的入口信息。启动信息使用 `Cache-Control: no-store`。

配置中的 assets 指向静态目录，index 指定该目录内的入口文件，默认值为 index.html。assets 缺省时提供 Cordis 启动页。静态文件的 HTTP、范围请求与路径处理由 axum、tower-http 和 url 承担。

监听套接字、专用线程、自有 Tokio 运行时和连接均属于组件效应。停用时发送关闭通知，等待服务器及线程结束，再释放效应。每次激活重新生成令牌。服务任务异常退出时撤回承载网络服务的效应，并保留错误。

M20 在接口末尾追加资源登记与撤回，按替换序号形成 `/_cordis/<插件>/<序号>/<入口>` 路径，再接入入口清单与 WebSocket。WebSocket 的 Origin、令牌检查和 UP/1 转发通道随该阶段实现；网络解析继续由插件进程承担，生命周期与依赖决策继续归核心中的唯一内核。

## 依赖

| 依赖 | 版本 | 用途 |
|---|---|---|
| cordis-sdk | 项目版本 | 原生组件、效应与 Web 接口 |
| serde | 1.0.229 | 配置和入口 DTO |
| serde_json | 1.0.154 | 页面启动信息序列化 |
| axum | 0.8.9 | HTTP 路由和服务器 |
| tower-http | 0.7.1 | 静态文件服务 |
| tokio | 1.54.1 | 插件自有网络运行时及关闭通知 |
| url | 2.5.8 | 页面地址与片段编码 |
| uuid | 1.26.1 | 每次激活的随机会话令牌 |

上述网络依赖归属于 HTTP 插件。web-api 使用 SDK 和 serde，供原生调用方与提供方共享接口定义；进程窗口按同一 UP/1 数据结构调用。

## 验收与后果

M16 通过真实 HTTP 请求检查默认页面、自定义入口、静态资源、启动信息和停用后的端口释放，并通过真实原生宿主取得 WebEntry。窗口据此验证页面显示、崩溃恢复和有序退出。M20 继续完成资源效应、页面隔离域、局部替换及转发通道验收。
