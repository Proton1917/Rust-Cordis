# ADR-0010 ABI 由本项目规定；结构化数据用 CBOR

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-11） |
| 影响 | `DOC-12` 全文；`DOC-13` §3.1、§7 |

## 问题

`ADR-0009` 选定原生动态库加稳定 C ABI。需要决定两件事：ABI 的类型布局由谁规定；接口方法中非基本类型的参数如何跨边界。

## 选项

### 布局的规定者

| 选项 | 内容 | 代价 |
|---|---|---|
| A1 | 使用 `abi_stable` | 布局由该 crate 的版本决定；该 crate 不提供跨边界的 `Future`，需要再加 `async_ffi` |
| A2 | 使用 `stabby` | 布局由该 crate 的主版本决定 |
| A3 | 本项目在 `DOC-12` 中规定全部布局，`cordis-abi` 实现 | 需要自行编写类型、蹦床与过程宏，并以 Miri 与布局测试保证正确 |

### 非基本类型的编码

| 选项 | 内容 | 代价 |
|---|---|---|
| E1 | 为每个数据类型生成 `#[repr(C)]` 镜像 | 追加字段会改变布局，违反 `DOC-11` §3.2 第 2 条 |
| E2 | `postcard`、`bincode` 等非自描述格式 | 追加字段后旧读取方无法解码 |
| E3 | CBOR（RFC 8949） | 每次调用有编解码开销 |

## 判据

1. ABI 主版本预期维持多年，跨越多次核心年度升级（`DOC-10` §2.1）。布局不能依赖第三方 crate 的发布节奏。
2. 其他语言今后可以按文档实现插件绑定。
3. 数据类型追加带默认值的字段时，新旧双方都能继续工作。
4. 编码格式本身有独立于实现的公开规范。

## 决定

选 A3 与 E3。

- A1、A2 不满足判据 1、2：布局的权威来源是第三方 crate 的源码，不是可独立阅读的规范。
- E1、E2 不满足判据 3。E3 满足判据 3、4。
- `DOC-12` §7.3 规定基本类型、字符串、字节串、接口对象原样传递，只有其他结构化类型走 CBOR，热路径上的常见参数没有编解码开销。

## 后果

- `cordis-abi` 包含 `unsafe` 代码，按 `B-2` 管理，`Y-6` 以 Miri 检查。
- 实现时可以参考 `abi_stable`、`stabby`、`async_ffi` 的设计，但不把它们作为依赖。
- CBOR 编解码使用 `ciborium`（`DOC-13` §7）。
