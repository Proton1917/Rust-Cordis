# ADR-0034 配置调和与管理持久化的运行时代码上限

| 项 | 内容 |
|---|---|
| 状态 | 已实施，交设计方复核（2026-11-13） |
| 影响 | DOC-13 §1.1；M12 配置、管理窗口、状态恢复与来源确认 |

## 问题

M12 的运行时同时承担核心命令、插件清单与配置、逻辑 scope 展开、disabled 调和、逐方法授权、管理叠加层、状态检查点、原快照回滚、整窗口替换、批次受理结果和已确认来源恢复。UPSTREAM-EXT 及 ADR-0031–0033 补充了其中的批次事务、配置组和终端相关装配要求。按 cloc 2.10 的 Rust 注释规则统计，运行时为 4304 代码行 / 4729 总行，超过原 2500 代码行上限。

## 已完成的职责调整

文件监视由 watch 插件承担，项目生成与验证命令位于 cordis-dev，原生库与 ABI 执行位于 cordis-host，进程组控制复用 cordis-process。运行时内部按配置及 scope 展开、清单与库存、管理请求、控制事务、批次结果、来源确认、状态存储、只读状态和命令分模块；长函数按启动、预备目标、执行、提交、恢复与退出步骤拆分。

## 决定

cordis-runtime 的目标设为 4500 代码行，上限设为 5500 代码行。沿用 DOC-13 §1.1 的 src 代码行计量，空行、普通注释与文档注释分别统计。运行时继续通过唯一核心的公开接口协调生命周期，开发工具、文件监视及插件代码保留各自的执行进程与依赖边界。

## 后果

管理事务共享配置、授权、部署引用与状态的同一份记录，保持失败恢复和磁盘记录的一致性。每个里程碑继续记录代码行 / 总行，超过目标时说明具体职责来源，超过上限时按项目规则提交 ADR。
