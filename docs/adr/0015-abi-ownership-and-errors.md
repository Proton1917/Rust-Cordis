# ADR-0015 ABI 所有权、错误与异步调用

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | `DOC-12` §4–§11；`DOC-13` §3.1、§3.3、`B-2`；M8 布局 |

## 问题

ABI v1 需要使服务、回调、缓冲、Future 与 Waker 在独立编译的库之间转交，并在释放、panic 和替换期间保持资源所有权及代码寿命。错误、异步结果、清理中的上下文和导出冻结都需要确定的调用协议。

## 选项

| 选项 | 错误通道 | 租约归属 | 代价 |
|---|---|---|---|
| A | 每个边界函数返回 `AbiStatus`，成功值和错误经输出指针交出 | 拥有值在创建时取得租约，转交移动，调用返回后归还 | 释放和 Waker 操作也携带错误指针 |
| B | 资源释放函数经独立全局错误回调报告 | 接收方取得租约 | 错误发生位置与接收方分离，转交期间需要额外协调 |

## 判据

1. 所有展开都在发生的一侧结束，错误能归属对应操作。
2. 释放函数、静态数据和正在返回的插件代码都有明确的库寿命。
3. apply、清理和 committed 依赖继续遵守第一阶段语义。
4. 参数与返回值保留 `DOC-12` §7.3 的直接类型映射。

## 决定

采用 A，具体契约由 `DOC-12` 规定。

- 所有函数返回 `AbiStatus`，成功输出与错误分离。`clone`、`drop`、`free`、Waker、描述符 `release` 和 Host 表均采用同一约定。panic 返回 `status=2/code=5`。释放阶段的错误允许空消息和详情，以代码表达故障。
- `AbiBuf` 增加 `library`，覆盖释放函数与静态数据；`AbiError` 的两个缓冲分别拥有租约。`AbiUnit` 表达单位结果，`AbiState` 表达模式名、版本和数据。
- 拥有输入在进入被调函数时转交，成功、失败及 panic 都由被调方处理。生成的蹦床先接管全部拥有输入，再执行可能失败的内容解码。`AbiOption` 的标志属于输入结构契约，0 对应空值，1 对应有效载荷。
- 拥有值创建时取得租约，clone 增加一份，转交移动既有租约。资源释放回调仅释放资源，调用方在回调返回后归还租约。装载器持有描述符及其组件函数的库引用；物理卸载在相关调用返回后调度。
- Future 的 poll 返回 `AbiStatus`，另以 `out_state` 表达 Pending 或 Ready。成功值的布局由对应方法返回类型确定。poll 与 drop 串行执行，Future 按 `Send` 管理；Waker 操作支持跨线程。
- Future 提前 drop 表达取消并释放保存的 Waker；apply 与异步效应按 A-7 运行至完成或协作结束。装载器在这类任务完成后处理清理与句柄退役。
- ctx 按加载纪元分配，保留至该纪元的 apply、任务、线程和效应清理结束。清理期间通过 get 访问 committed 依赖。`is_current` 描述目标纪元，句柄退役后访问返回 code 4。
- Host 槽 20、21 分别为 `effect_settled`、`effect_dispose`，都返回单位结果的 Future。scope 在效应体执行期间有效；effect 句柄保留至所属纪元清理结束。
- 状态导出器有 `export` 和 `thaw` 两个函数。导出失败或替换中止时，宿主调用 thaw 解除冻结。
- Host `log` 的 ctx 0 是库级诊断入口。Rust Drop 与 Wake 的错误经此入口记录；显式释放和克隆直接返回 Result。
- B-2 覆盖 unsafe 块、函数、impl 与属性，以及宏生成的固定 extern 调用模板。源码审计用开发依赖 syn 解析，宏模板的 SAFETY 依据保存在源码并进入生成文档注释。
- `cordis-abi` 的运行时依赖为 serde 与 ciborium；标准库负责 Future、Waker、引用计数和 panic 捕获。源码审计依赖归开发构建。
- Rust 侧 Environment 的构造是 unsafe 入口，其调用者保证宿主表内全部函数遵守结果初始化、所有权和错误协议；安全 HostClient 从这个已建立契约的环境调用。
- 对象的 vtable 原始指针从完整静态虚表派生，指针来源覆盖首部 size 声明的全部字节。Object::new 接收该原始指针，克隆保留其来源；ObjectHeader 引用作为首部读取视图，方法槽读取使用完整虚表原始指针。
- 组件记录通过各自的 size 字段确定步长。读取方先验证最低大小和对齐，再读取已知前缀；组件表的指针来源覆盖全部记录。尾部追加字段后，多条记录保持同一读取协议。

## 后果

`DOC-12` 的布局、候选实现和 M8 布局记录共同表达上述契约。安全包装负责所有权、错误读取和源侧释放，SDK 与宏通过这些包装实现类型转换。布局冻结发生在 M8 的行为与 Miri 验证通过之后。
