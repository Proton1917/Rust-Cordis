# ADR-0023 前端插件经通用插口接入，浏览器中无内核

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-12） |
| 影响 | `DOC-15` §3、§4.2、§8 第 9 条、§9、§10、§11、§13、§15（`M10`、`M12`、`M20`）、§16（`AU-7`、`AU-14`、`AU-15`）；`DOC-11` §10；`docs/16-up1-protocol.md` |

## 问题

项目所有者要求前端代码也作为插件插入核心，与其他插件同样声明依赖、热替换、回滚。`DOC-15` §11 的原方案让浏览器页面运行上游 JS 版 cordis 作为前端内核，核心只经 WebSocket 通知页面替换模块。该方案有三处问题：

1. 浏览器中的前端内核是第二个内核，前端组件的实例、依赖与纪元不由核心决定，违反 `Q0` 推论 5。
2. 前端组件不能经核心注入后端服务，前后端之间仍需另设 HTTP 接口。
3. `[web]` 段只存在于进程插件的清单中，原生插件无法附带前端。

## 选项

### 浏览器中运行什么

| 选项 | 内容 | 代价 |
|---|---|---|
| A1 | 上游 JS 版 cordis 作为前端内核（原方案） | 第二个内核；前端不在核心的依赖图中 |
| A2 | 网页宿主 `cordis-web`：不含内核，只执行核心经 `UP/1` 下发的指令，与 `cordis-host` 同构 | 每次装载与替换都需核心与页面之间往返消息 |

### 页面的 `UP/1` 连接由谁终结

| 选项 | 内容 | 代价 |
|---|---|---|
| B1 | 核心直接监听 WebSocket | HTTP 与 WebSocket 解析进入核心进程，扩大核心处理不可信输入的范围 |
| B2 | `http` 插件终结 WebSocket，经转发通道把每个页面作为独立连接交给核心 | 多一跳转发；`http` 插件崩溃时全部页面断开并重连 |

### 原生插件如何附带前端

| 选项 | 内容 | 代价 |
|---|---|---|
| C1 | 拆成两个插件：原生后端插件与独立的前端插件 | 一个功能两个版本号，替换与回滚不能作为一个单元 |
| C2 | 原生插件也可带清单 `cordis-plugin.toml`（`socket = "native"`），其中声明 `[web]` | 原生插件多一种目录形态 |

## 判据

1. 系统中只有一个内核（`Q0` 推论 5）。
2. 核心进程不承担网络协议解析（要求 1）。
3. 前端组件与其他插件使用同一套依赖、注入、效应、热替换与回滚。
4. 一个全栈功能的前后端作为一个单元替换与回滚。

## 决定

选 A2、B2、C2。

- 浏览器页面是通用插口上的网页宿主，运行 `cordis-web`（TypeScript SDK 的浏览器构建），不含内核。
- 核心为每个页面上的每个前端组件建立子实例；每个页面是一个独立 realm；页面关闭时核心回收其子实例与效应。
- 前端组件经 `UP/1` 注入任何插口上的服务，前后端之间不另设 HTTP 接口。
- `http` 插件（原生，默认自成一组）提供静态资源、`cordis.web@1` 与 WebSocket 终端，用 `channel_open`、`channel_frame`、`channel_close` 转发页面连接；核心对每个通道独立执行 `CP-2`、`CP-3`、`CP-8`，不监听网络端口。
- 插件清单的 `socket` 取 `native`、`process`、`web`；`[web]` 段可与前两者组合成全栈插件，与 `web` 组合成前端插件。全栈插件的前后端版本相同，作为一个单元替换与回滚。

## 后果

- `M10` 的 `UP/1` 规范定义转发通道消息，连接抽象与传输无关；实现与测试在 `M20`。
- `M12` 的清单解析支持 `socket = "native"`；`M20` 加入 `socket = "web"` 与 `[web]`。
- 浏览器不卸载已导入的 ES 模块，开发中反复替换会在页面内累积旧模块，刷新页面释放。
- 上游 JS 版 cordis 不进入本项目的交付物。
