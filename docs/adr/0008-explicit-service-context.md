# ADR-0008 服务调用的定义点与使用点

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-11，UTC−08:00） |
| 影响 | `DOC-02` §5.3、§6 的 `Scoped<K>` 接口；`S-SVC-11`–`S-SVC-13` |

## 问题

`ICP-06`、`SHD-01`、`SHD-04` 与 `LOG-07` 同时要求服务内部访问采用定义点规格，访问元数据继承外层使用点的拦截。`Scoped<K>` 需要显式保存这两类上下文，并在嵌套服务调用时继续传递。

## 选项

| 选项 | 内容 | 后果 |
|---|---|---|
| A | 服务作者逐次传递定义点上下文与使用点上下文 | 每个服务重复实现元数据传播和日志来源选择 |
| B | `Scoped<K>` 保存提供点、请求代码定义点及使用点，提供类型化依赖访问 | 三种信息各有明确读取接口，嵌套调用由相同规则构造句柄 |

## 判据

1. `DOC-00` `P5`、`P6`：服务依赖在定义点强制执行，效应归属由显式调用方表达。
2. `UPSTREAM` `service.ts:57–70`：声明元数据与调用方携带的拦截层共同决定访问元数据。
3. `SHD-04`：改变调用方隔离视图时，服务内部的依赖绑定仍来自其定义点。
4. `LOG-07`、`LOG-08`：日志采用当前服务名称，外层拦截可以覆盖名称，嵌套调用后外层名称继续有效。

## 决定

采用 B。`Scoped<K>` 提供以下接口：

- `caller()` 返回原使用点，用于登记调用所产生的效应，并承载使用点的隔离和拦截视图。
- `definition()` 返回绑定的提供上下文。
- `requester()` 返回发起当前依赖访问的代码定义点，对应上游 `@@caller`；直接访问时等于使用点，嵌套访问时等于外层服务的提供点。
- `meta()` 从 `requester()` 定位声明元数据，再合并 `caller()` 的拦截视图。
- `dependency::<D>()` 从当前服务的定义点解析 `D`，得到的句柄以当前定义点为 `requester()`，继续携带原 `caller()`。
- `with_value(value)` 创建服务值的派生句柄，保留上下文信息。
- `logger()` 采用当前服务定义纤程作为来源，并解析外层的日志拦截。

## 后果

服务的扩展 trait 可以直接表达上游代理、可调用服务与关联访问的可观察行为。普通 Rust 方法通过这些显式接口获得调用信息；保存定义点 `Context` 的服务仍可直接使用该上下文解析依赖。

`DOC-02` §5.3 的职责保持原定义：效应归 `caller()`，服务内部的依赖解析归 `definition()`，拦截来自 `caller()`。`requester()` 补足上游代理中独立保存的访问代码定义点，用来执行声明元数据与关联键访问规则。
