# Rust 内核的状态与执行

## 1 内核对象

`Context` 表达操作发生的范围，`Fiber` 表达实例，`Effect` 管理该次登记的释放，`Registry` 保存可挂载的组件定义。组件可以在 Rust 程序内直接使用；部署运行时通过同一个内核管理远端插件。内核预算为 6000 代码行。动态库、网络与文件监视分别由宿主和插件承担。

## 2 服务绑定与视图

服务键标识依赖的值类型。跨语言边界使用带版本的名称；进程内 Rust 接口由类型化键取得。`isolate` 为服务选择独立命名域，`intercept` 叠加调用元数据，子上下文继承父视图。实例激活时保存已提交的绑定。提供方变化由内核传播，消费方在新的加载代重新取得服务。

## 3 锁与调度

内核在锁内计算目标状态并收集待执行动作，释放锁后调用用户代码。事件派发拍下监听器快照，逐个执行时尊重已撤回的登记。一次生命周期迁移从开始运行到完成或协作停止，期间到达的新目标归入同一轮调和。

状态锁同时保护当前暂停清理任务的计数。宿主拒收清理任务时登记错误并增加计数；显式恢复时取走错误并减少计数。计数为零时，实例稳定等待和清理恢复直接省去全表错误扫描；存在暂停任务时继续按组件树查询具体错误。暂停任务持有所属实例或效应的句柄，记录在恢复完成后释放。

## 4 架构约束

| 条款 | 实现约束 |
|---|---|
| A-1、A-2 | 单一内核状态锁保护可变状态，对外句柄支持跨线程共享。 |
| A-3、A-4 | 回调、Future 轮询与等待在锁外进行；事件派发使用快照。 |
| A-5、A-6 | 串行处理受影响实例；每个实例至多保留一个加载或清理迁移。 |
| A-7、A-8 | 过时加载在步骤边界协作交还控制。异步释放由显式释放或所属实例的清理驱动。 |
| A-9、A-10 | 内核驱动的组件错误归到实例，错误保留登记位置；调用方直接派发的回调依其接口传播错误。 |
| A-11、A-12 | 内核采用第 9 节的依赖范围，执行器与时钟由宿主注入。 |

## 5 生命周期

依赖满足后执行 `apply`；加载失败时已经登记的动作仍由对应实例清理。组件自行启动的定时器、连接和线程应登记相应释放动作。进程退出会撤回核心中的连接资源，外部已经提交的业务写入由其数据所有者管理。

## 8 存储服务示例

先挂载消费方，它等待 `Database`。提供方加入后消费方激活，登记监听器；移除提供方时，消费方先撤下监听器，再进入等待。提供方重新挂载会使消费方取得新绑定。释放根上的组件后，三张表中的服务、监听器、组件登记回到挂载前的状态。[运行示例](../crates/cordis/examples/plugins.rs)
