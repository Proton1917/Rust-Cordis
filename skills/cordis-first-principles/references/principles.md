# 职责放在哪里：第一性原理

Rust-cordis 的每个设计都先回答一个问题：**决定这件事正确结果的事实，由谁唯一掌握？** 掌握事实的一方承担这项职责。写插件、拆插件、给接口加字段时都按这个问题决定位置。仓库的 `AGENTS.md`“第一性原理”一节是同一套判据的完整版本。

## 谁掌握什么

| 事实 | 唯一掌握者 | 对插件作者的含义 |
|---|---|---|
| 实例身份、依赖是否满足、加载与清理时机、替换与回滚 | 核心中的内核 | 不在插件里自己判断“依赖到了没有”“该不该重启”；声明依赖，由核心调度 apply 与清理 |
| 一次调用来自哪个实例或页面 | 核心（它掌握连接） | 用 `caller(metadata)` 读取可信身份，不信任调用方自报的身份字段 |
| HTTP 请求头、Cookie、会话、认证结果 | 终结 HTTP 的 http 插件与处理方 | 认证与会话写在处理方插件中；核心只转交不透明数据，不要指望核心解析它们 |
| 业务数据、领域规则、业务状态 | 业务插件 | 数据存在插件自己的数据目录或数据库，状态经导出器迁移 |
| 机密的值 | secrets 插件 | 经 secrets 服务按实例授权读取；配置里只写机密的键名 |
| 代码在哪个进程运行、哪些插件共享故障域 | 部署配置（`cordis.toml` 的 group） | 分组是部署决定，不写进代码；同一份插件可以换组而不改源码 |

## 由此得出的规则

每条给出常见的错误写法和正确做法。

**P-1 不为一个应用要求核心加功能。** 需要的能力先找已有机制：效应、依赖注入、`scoped` 与 `intercept` 元数据、资源对象作为参数转交、`cordis.manage@1` 授权、动态调用。确实缺少时，按任何应用都适用的通用能力提出。
- 错误：为某个应用的任务调度，要求核心增加“按订单排队”的接口。
- 正确：任务队列是业务事实，写成一个提供 `jobs@1` 服务的插件。

**P-2 协议由终结它的插件处理。** 谁解析协议，谁负责它的语义。
- 错误：把 Cookie 或令牌放进 UP/1 元数据，期望核心校验。
- 正确：处理方插件读取请求头并校验；页面连接的请求头快照经 `cordis.http-page@1.0` 查询（见 [HTTP](http.md)）。

**P-3 机密不离开 secrets 服务。** 不放进环境变量、配置值、日志、错误信息、导出状态或接口返回值。
- 错误：在 `cordis.toml` 或插件配置里写 `api_key = "..."`；启动脚本 `export API_KEY=...`。
- 正确：配置写 `api_key_secret = "MY_KEY"`，secrets 插件的 `grants` 把 `MY_KEY` 授权给需要的实例，插件运行时经 secrets 服务读取。

**P-4 身份只信核心给的。** 授权判断依据 `caller(metadata)` 的 `instance`（后端）或 `page_of`（页面），不依据参数里的用户名、实例名。
- 错误：接口参数带 `caller: String`，提供方据此放行。
- 正确：提供方以 scoped 方式提供服务，从元数据读取直接调用方身份；页面调用方没有 `instance`，需要显式按 `page_of` 授权。

**P-5 一个插件一类事实。** 插件按“谁掌握这类数据和规则”划分，接口按使用方需要的能力划分。一个插件同时持有两类互不相关的状态时，替换其中一类会连带重启另一类。

**P-6 跨进程只有异步契约。** 跨进程事件是通知，不等返回值；需要回答时用服务方法。同步共享内存与闭包只在同一进程内成立。

**P-7 跨机器协作经插件自己的网络接口。** 一个核心管理一台机器上的插件进程，Rust-cordis 不在核心之间组网。另一台机器上的执行端通过业务插件提供的 HTTP 接口领取任务、提交结果，接口与认证由该插件定义。

**P-8 通用优先于特例。** 方法名确实来自配置或外部输入时才用动态调用；数据结构新增字段给缺省值并提升接口次版本，不为某个使用方另开一个接口版本。

**P-9 发布物不带本机信息。** 发布包、日志与对外存档不包含本机用户名、`/Users/` 或 HOME 路径、私有项目名。依赖写公开仓库地址，不写 `file://` 本机路径。检查按完整字节进行（见 [打包](packaging.md)）。

## 交付前自查

- 新增的每项职责，能说出它依据的事实由谁掌握，以及为什么放在当前插件。
- 没有为单个使用方新增特例接口或配置分支。
- 机密只以键名出现；日志、错误信息与导出状态中没有机密和业务载荷的原文。
- 授权依据核心提供的调用方身份。
- 依赖、配置和发布物中没有本机路径。
