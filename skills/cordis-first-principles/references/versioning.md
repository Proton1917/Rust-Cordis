# 接口版本与升级

接口以 `<名称>@<主版本>.<次版本>` 标识，例如 `kv@1.2`。WIT 包版本 `cordis:kv@1.2.0` 的主版本与次版本对应接口版本，修订号不参与匹配。接口由使用方与提供方共同依赖，它的版本决定了替换时谁需要一起变。

## 次版本：只做追加

在同一主版本内，下列修改允许，次版本加一：

1. 在接口末尾追加方法。
2. 为记录类型追加带缺省值的字段（Rust 用 serde 缺省值）。
3. 为事件载荷追加带缺省值的字段。

使用方注入 `kv@1.2` 表示需要主版本 1、次版本不低于 2。提供方提供 `kv@1.5` 时匹配；提供 `kv@1.1` 时使用方保持 Pending。使用方调用超出提供方次版本的方法时，SDK 在调用前返回错误。

所以次版本升级的顺序是：先替换提供方，再替换需要新方法的使用方。

## 主版本：不兼容修改

除上面三项之外的修改都不兼容：删除或改名方法、修改参数或返回类型、改变已有方法的行为语义、删除字段。不兼容修改发布新主版本，例如 `kv@2.0`。

新旧主版本是两个不同的接口，可以同时存在于一个核心中。过渡有三种做法：

| 做法 | 适用 | 操作 |
|---|---|---|
| 提供方同时提供两个主版本 | 同一份数据能同时满足两套语义 | 提供方的 provides 同时列出 `kv@1` 与 `kv@2`；使用方逐个改为注入 `kv@2`、逐个替换 |
| 适配器插件 | 新提供方只实现新版本，旧使用方暂时不改 | 新增一个插件，注入 `kv@2`、提供 `kv@1`，在方法中转换 |
| 一次批量替换 | 提供方与全部使用方由同一团队维护、可以同时发布 | 把提供方和所有使用方放进同一批替换：watch 会把同一防抖窗口内的变化作为一批提交，也可由持有 `cordis.manage@1` 授权的插件调用 `replace_batch`。批内任一项失败，整批回滚 |

不要在同一主版本里偷偷改变方法语义。使用方看到的接口名没变，核心也会照常匹配，错误只会在运行时出现。

## 退役旧主版本

1. 在 `cordis.toml` 与叠加层 `state/instances.toml` 中确认没有实例还注入旧主版本。
2. 提供方从 provides 中删除旧主版本，或停用适配器插件。
3. 保留旧主版本的契约套件，直到所有部署都完成升级。

## 状态模式版本

状态模式的版本与接口版本相互独立。接口没变时，内部状态格式也可能变。

- 新实现声明自己接受的状态版本范围，在 apply 中把旧版本转换成新格式；转换写在接收该版本的新实现里。
- 替换失败时核心把替换前的原快照交回旧版本，回滚不受影响。
- 替换已经确认之后再降级，旧实现收到的是新格式的状态。降级前确认旧实现能接受当前状态版本，否则先发布一个能读写新格式的旧逻辑版本。

## 契约套件

契约套件针对一个接口主版本编写。次版本追加方法时，在同一套件里追加断言；新主版本另写一个套件。提供方升级后用 `cordis verify` 重新取得验证印记，开启 `require_verified` 的部署只装载有印记的库。
