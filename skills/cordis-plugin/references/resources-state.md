# 资源与状态

## 资源归属

| 条款 | 写法 | 需要纠正的写法及原因 |
|---|---|---|
| PR-1 | 通过 `ctx.spawn` 启动异步任务 | 任意执行器中的脱离任务会在插件替换后继续执行旧代码 |
| PR-2 | 使用 `ctx.spawn_thread`，或在效应中创建线程并在清理中通知退出和 join | 仅丢弃线程句柄会留下仍在运行的线程 |
| PR-3 | 使用插件自己的 Tokio 运行时，并把它的关闭登记在效应中 | 直接调用全局 `tokio::spawn` 依赖的运行时属于插件的 Tokio 实例 |
| PR-4 | 缓存可用 static；业务状态通过导出器迁移 | 新库有新的 static，替换时其中的业务状态会丢失 |
| PR-5 | 使用注入接口和事件交换数据、资源句柄 | 原始指针或跨插件 static 会使旧库的生命周期约束失效 |
| PR-6 | 在效应中取得资源，并登记 `defer` 或 `defer_async` | 单独依赖对象 Drop 会失去明确的停用时点 |
| PR-7 | 使用 `ctx.data_dir()` 下的持久文件 | 把数据混写进构建目录会受到清理和其他实例构建的影响 |
| PR-8 | 编译策略为 `panic = "unwind"` | abort 策略使 panic 终止整个宿主分组 |

`ctx.spawn_thread` 的函数接收上下文，循环通过 `context.is_current()?` 判断退出，并采用有界等待。异步任务使用 `ctx.sleep`，任务或线程持有的服务和上下文在效应清理中释放。

`ctx.spawn` 负责任务归属与清理；任务返回错误后结束，恢复策略由插件实现。长期后台循环遇到自身暂时冻结时，释放状态锁，通过 `ctx.sleep` 等待下一轮，并按当前纪元决定结束。注入服务的暂时拒绝按该接口的错误契约处理。

## 可逆效应

同步资源使用 `ctx.effect(label, |scope| { scope.defer(cleanup) })`。异步取得资源使用 `effect_async`，异步清理使用 `scope.defer_async`。同一效应内的清理按逆序逐项等待；顶层效应按逆序启动清理，可以并发执行。

清理保持实际资源所有权：文件句柄、监听器、任务或线程句柄随闭包保存，清理运行时释放或等待它们。服务调用及事件派发前结束本地数据锁的临界区，使重入回调可以继续执行。

## 状态迁移

在 `Component::state()` 声明模式与版本范围。加载时读取 `ctx.inherited_state()`，核对 `schema()` 和 `version()` 后用 `decode::<T>()` 恢复。缺席状态使用业务初始值；不支持的状态版本返回明确错误。

`ctx.export_state(schema, version, exporter)` 返回 `Frozen`；需要先把冻结标志放入服务对象时，用 `Frozen::new()` 配合 `export_state_with`。本地状态写路径取得状态锁后，在同一临界区检查冻结标志和更新状态。向调用方返回结果的一次写请求可以使用 `frozen.check()?`；长期后台循环按上文处理暂时冻结。导出器通过同一把锁取得完整快照。

冻结发生在导出读取快照之前。锁内检查让已经进入写入临界区的操作完整进入快照，随后到达的写入读到冻结状态。锁外预检查可能先通过、再等待状态锁，最终在导出完成后修改旧状态，因此检查与更新共同持锁。

跨服务写入要明确权威状态、提交点和错误恢复规则。快照字段表示外部已提交结果时，在锁内准备候选并登记在途操作，释放锁后调用服务，确认提交后更新已提交值。导出器通过同一把锁识别在途操作；结果待确认时返回明确的繁忙错误，使本次导出中止并由核心解冻。本地状态作为权威时，明确外部副本的重发与对账规则。外部写入的错误结果按接口的幂等和提交语义解释，数据提交与通知派发分别判断。

导出覆盖热替换、定期检查点和有序退出。导出失败会解除冻结；候选失败时，核心将替换前原快照交回旧版本。状态版本转换放在接收该版本的新实现中。
