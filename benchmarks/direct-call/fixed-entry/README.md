# 固定入口的短标量调用

本实验衡量已绑定的同步标量调用。提供方以同一份源码导出 ABI 1.2 类型化服务和实验用 `cordis_benchmark_entry_v2`，两个入口调用同一个 `Store::value` 实现。消费方在独立 Cargo 工作区编译。两份库由基线宿主在同一进程内运行，消费方另持有固定入口库的装载句柄。计时开始前，每条路径的服务对象均已绑定并持有自己的计数实例。

固定表定义加载、绑定、调用和关闭四个操作。加载方把 CBOR 状态块连同源侧释放函数移交给提供方；提供方接受状态模式和版本后持有业务值，加载返回时输入已经释放。消费方分别检查成功加载与模式拒绝的输入释放。绑定按接口主版本、方法名和签名取得本加载代的方法编号。签名冲突在绑定阶段返回错误。同步调用借用参数并写入调用方提供的结果缓冲；本例可复用一个空参数数组的编码，每次读取在栈上保留九字节的 u64 结果空间。实例关闭先于消费方释放库句柄。

## 对照与门槛

采用提交 `2edc244cae71bd895d55b062fd20c3acd1318cb2` 的已展开源码、SDK、已构建的 release 核心和宿主。两端固定使用 Rust 1.96.0 及基线依赖锁文件，分别保存 Cargo 最终解析的锁文件。应用把两个插件放入同一分组，周期检查点和确认等待设为零。每条路径从业务值 100 开始。机器、编译器和每组原始结果随实验保存。

探索轮单列，正式测量十组，两个路径按组交替先后次序。每路预热 10,000 次；吞吐用连续 100,000 次调用的总耗时求得。紧接着分别计时 2,048 次单调用，以最近秩法取 p99，两个路径使用同一个单调时钟。延迟包含读时钟的开销。每个正式配对计算候选与基线的吞吐比和 p99 比，吞吐比下限为 0.95，p99 比上限为 1.05。十组在同一指标上均越界时，该候选停止发行验收；十组两项指标均达标时，才进入异步请求、资源交接与业务负载验收。其余结果记为待确认。

从仓库根执行以下命令，第二个路径为新建的实验目录，运行时限取该包剩余授权时间：

```sh
conda run --no-capture-output -n base python benchmarks/direct-call/fixed-entry/run.py \
  target/revision-2edc244/baseline target/revision-2edc244/p8-scalar --seconds 210
```

`raw.json` 保存探索轮和十组正式样本；`result.json` 给出逐组指标、配对中位数和本候选的标量判定。运行工具把本实验源码复制到基线检出的独立基准目录，从而使用固定提交的 SDK。主线的发布 ABI 与该实验分开发行。标量门槛衡量这里的绑定、CBOR 编码与调用约定；其他编码或调用约定需要各自的对照数据。
