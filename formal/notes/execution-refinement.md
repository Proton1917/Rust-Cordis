# 原生原子操作与异步清理

## 租约的分步执行

`Concurrency.State` 同时保存真实计数的抽象值、调用者持有数、借用源租约数、等待 CAS 的读取值以及计数修改历史。每次 clone 先把一份现有租约转入借用阶段；成功 CAS 归还原锚点并交付一份新租约。CAS 失败返回读取阶段，整数溢出归还原锚点。

已证明的计数恒等式是 `count = held + reading + attempts.length`。因此，任何读值或 CAS 尝试仍保有的锚点都会阻止计数归零。达到零后，所有可取得新引用的阶段均为空，零成为吸收状态。

原子读取可以选择计数历史中的任意值。模型允许过时读取，退休位与计数之间采用独立观察。计数历史出现零时，当前计数仍为零，因此 reaper 读取到过时的零也能安全取出映像。退休观察、零观察、取得映像锁及 `Option::take` 分别占据独立步骤；任意交错保持卸载时计数为零且没有在途 clone，映像至多取出一次。

这里的外部调用条件是 ABI clone 在取得新引用时持续持有现有源租约。Rust 原子类型和内存安全、外国调用者遵守 ABI、操作系统动态库实现构成环境契约。该模块建立的是上述原子原语和所有权操作的微步骤语义。

## Future 的通知与销毁

`AsyncSemantics.FutureState` 区分排队、轮询、睡眠、完成、已析构和已归还额度。轮询入口消费原通知；轮询期间的 wake 保留为通知位，Pending 据此重新进入队列。取消只请求析构；同步 poll 返回后才能执行析构，后续步骤归还 Permit。任意事件迹保持单次析构与单次归还，投影满足 `NativeOwnership.CallbackInvariant`。

串行清理沿用 `Execution.CleanupState` 的待执行、当前执行和已完成三段。秩为两倍待执行数、当前执行数与终态发布计数之和。开始回调、回调返回和发布终态分别使秩下降，其余观察及等待事件保持或降低秩。对于每个未完成后缀最终出现有效派发或回调返回的调度，证明清理最终完成，并且完成列表精确等于最初注册栈的逆序。宿主永久拒收与回调永久等待属于活性前提的边界。

## 目录容量

`Routing.BoundedPeer` 将实际 HashMap 的键域表示为无重复有限列表，并与 `Peer.entries` 建立逐键对应。分配前沿的新鲜性由原有引用所有权不变量推出。插入使用真实键域长度进行额度判断，移除使用过滤，提交保持键域。任意插入、移除和批次提交迹保持目录容量与原有引用所有权。

## 源码执行证据

`tools/execution_semantics_probe.py` 原样提取 lease 的 count、retired、reap、acquire、release，以及 callback 的 Usage、Admission、Permit、Admitted 类型和实现块。探针使用实际 `std` 原子操作、Arc、HashMap、Future、Pin 和 Waker；动态库与文件副本对象记录析构次数，映像统计接口为独立支撑。

Lean 生成 216 个租约输入，涵盖零、普通计数及 `usize::MAX` 边界。另执行 20 个通知 Future 在不同轮询位置析构的调度。四个真实源码变异分别修改递增、递减、映像取出条件和字段析构顺序，全部必须被拒绝。探针重新构建证明输入，独立核对完整且唯一的向量域，校验执行前后源码摘要，原子写入验证状态。真实动态库及取消时同步 poll 的集成场景由现有 `cordis-host` 测试执行。
